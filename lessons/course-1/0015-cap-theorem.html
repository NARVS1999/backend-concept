CAP Theorem

Bakit hindi pwedeng magkaroon ng lahat ng magandang katangian ang isang distributed system.

Lesson Goal Maunawaan ang CAP theorem at kung paano ito nagde-drive ng architectural decisions sa distributed systems.

Ang Tatlong Katangian

  • Consistency — Bawat read ay nakakakuha ng pinakabagong write (o error)
  • Availability — Bawat request ay nakakatanggap ng response (kahit hindi latest ang data)
  • Partition Tolerance — Patuloy na gumagana ang system kahit may network failure sa pagitan ng nodes

Ang Theorem: Choose 2 out of 3

Sa isang distributed system, kapag may network partition (P), kailangan mong pumili sa pagitan ng Consistency (C) at Availability (A).

CP Systems (Consistency + Partition Tolerance)

  • Kapag may partition, magha-hang o mag-e-error ang system hanggang ma-resolve
  • Example: Traditional RDBMS, MongoDB (default), HBase
  • Use case: Banking systems, kung saan bawal ang maling data

AP Systems (Availability + Partition Tolerance)

  • Kapag may partition, patuloy na tumatanggap ng writes at nagre-return ng responses — pero pwedeng hindi consistent
  • Example: Cassandra, CouchDB, DNS
  • Use case: Social media feeds, kung saan okay lang ang slight inconsistency
Reflection Isulat sa sarili mong salita kung saan babagsak ang mga common databases (MySQL, MongoDB, Cassandra) sa CAP spectrum.

Quiz

Summary

  • CAP = Consistency, Availability, Partition Tolerance
  • Kapag may network partition, pumili sa pagitan ng C at A
  • CP: consistent pero pwedeng hindi available (banking)
  • AP: available pero pwedeng inconsistent (social media)
Interview Angle "Bakit hindi pwedeng ma-guarantee ang parehong consistency at availability kapag may network partition?"
