Phase 5: Security Fundamentals — Lesson 1 of 3

Authentication vs Authorization

Sino ka? (Authentication) at Ano ang pinapayagan mong gawin? (Authorization)

Lesson Goal Maunawaan ang pagkakaiba ng authentication at authorization, session-based vs token-based auth, at JWT.

Authentication vs Authorization

  • Authentication — "Sino ka?" Pag-verify ng identity (login with username/password, OAuth, biometrics)
  • Authorization — "Ano ang pwede mong gawin?" Pag-check kung may permission ang isang authenticated user

Session-based Auth

  • Server ang nagke-keep ng session data (in-memory o sa DB)
  • Client ay nagse-send ng session ID (cookie)
  • Problema: hindi pwedeng i-scale horizontally agad (kailangan ng shared session store)

Token-based Auth (JWT)

  • Server ay nag-i-issue ng token (JWT) na naka-sign
  • Client ay nagse-send ng token sa Authorization header
  • Server ay nagve-validate ng signature — hindi kailangan ng session storage
Important Ang JWT payload ay naka-encode lang, hindi naka-encrypt — kahit sino ay pwedeng mag-decode (base64). Huwag maglagay ng sensitive data sa JWT payload!

Summary

  • Authentication = identity verification; Authorization = permission checking
  • Session-based: server-side state, pwedeng i-revoke agad
  • Token-based (JWT): stateless, scalable, pero hindi pwedeng i-revoke agad
  • JWT payload ay encoded lang — wag lagyan ng sensitive data
Interview Angle "Bakit hindi dapat naka-store ang sensitive data sa JWT payload?"
