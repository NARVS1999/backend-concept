Phase 5: Security Fundamentals — Lesson 3 of 3

Password Handling

Paano i-store ang passwords nang tama — hindi plain text, hindi MD5.

Lesson Goal Maunawaan ang pagkakaiba ng hashing at encryption, at kung paano gamitin ang bcrypt/argon2 para sa secure password storage.

Hashing vs Encryption

  • Hashing — One-way function. Hindi pwedeng i-reverse para makuha ang original input. deterministic (same input = same hash).
  • Encryption — Two-way function. Pwedeng i-decrypt para makuha ang original data gamit ang key.

Para sa passwords, gumamit ng hashing, hindi encryption. Bakit? Kasi hindi na natin kailangang malaman ang original password — kailangan lang nating i-verify na ang input ng user ay match sa naka-store na hash.

Bakit Hindi Sapat ang MD5?

  • MD5 ay napakabilis — kayang mag-hash ng bilyong passwords per second gamit ang GPU
  • May mga kilalang collisions (two different inputs producing same hash)
  • Vulnerable sa rainbow table attacks (pre-computed hash tables)

Tamang Password Hashing

bcrypt

  • Designed specifically para sa password hashing
  • Mabagal — intentional, para mahirap i-brute force
  • May cost factor (work factor) — kayang i-adjust para lumaban sa faster hardware
  • Automatic na may salt (random data na idinadagdag sa password bago i-hash)

Argon2

  • Winner ng 2015 Password Hashing Competition
  • Mas moderno kaysa bcrypt
  • Resistant sa GPU at ASIC attacks (memory-hard)

Mini-Project: Password Hashing

Mag-implement ng password hashing gamit ang bcrypt. I-explain kung bakit hindi dapat plain-text o simpleng MD5.

Summary

  • Passwords: hash, wag i-encrypt
  • MD5/SHA1: masyadong mabilis, hindi para sa passwords
  • bcrypt: slow + automatic salt + configurable cost factor
  • Argon2: modern standard, memory-hard
