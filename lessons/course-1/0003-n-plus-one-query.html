N+1 Query Problem

Isang common performance issue sa ORMs na pwedeng magpabagal ng application mo nang sobra.

Lesson Goal Matukoy kung ano ang N+1 query problem, paano ito nangyayari, at paano ito i-fix gamit ang eager loading.

Ano ang N+1 Query Problem?

Ang N+1 ay nangyayari kapag nag-query ka ng isang listahan ng records (1 query), tapos para sa bawat record, may hiwalay pang query (N queries).

Halimbawa — kumuha ng lahat ng users at ang kanilang orders:

// 1 query: kunin lahat ng users
$users = User::all();

// N queries: para sa bawat user, kunin ang orders
foreach ($users as $user) {
    $orders = $user->orders; // ito ay isa pang query per user
}

Kung may 100 users, ang total queries ay 1 + 100 = 101 queries!

Eager Loading vs Lazy Loading

  • Lazy Loading — Ang related data ay nila-load lamang kapag in-access. Ito ang dahilan ng N+1.
  • Eager Loading — Ang related data ay nila-load na agad gamit ang JOIN o isang hiwalay na query na may WHERE IN.

Sa Laravel, ang fix ay gamit ang with():

// Eager loading — 2 queries lang
$users = User::with('orders')->get();

Paano Ma-detect sa Production?

  • Gamit ang database query log — i-monitor kung ilang queries ang na-e-execute per page load
  • Gamit ang ORM tools (Laravel Debugbar, Django Debug Toolbar)
  • Manual inspection ng SQL logs

Mini-Project: Hanapin ang N+1

Magpagawa ng agent ng intentionally-buggy code na may N+1 issue. Ikaw mismo ang mag-identify at mag-fix — huwag muna hayaan i-fix ng agent agad.
