Background Jobs & Queues

Paano i-offload ang mababagal o non-urgent tasks para hindi maka-block ang user request.

Lesson Goal Maunawaan kung kelan gagamit ng background jobs, paano gumagana ang message queues, at ang tradeoffs ng sync vs async processing.

Sync vs Async Processing

SynchronousAsynchronous (Background Job)
Naka-block ang user hanggang mataposNagfa-fail ang user pag may error
Simple i-implementComplex — kailangan ng queue infrastructure
Direct feedback sa userNeed feedback mechanism (email, websocket, polling)

Kailan Gumamit ng Background Jobs?

  • Pag-send ng email — hindi naman kailangan agad ng user
  • Image/video processing — CPU-intensive
  • Report generation — matagal gawin
  • Webhook calls — third-party na pwedeng mabagal
  • Data synchronization sa external services

Message Queue Technologies

  • Redis Queue — Simple, gamit ang Redis lists
  • RabbitMQ — Full-featured, may routing at exchanges
  • Amazon SQS — Managed, scalable, walang infrastructure kelangan
  • Bull / Sidekiq — Popular job libraries para sa Node.js at Ruby
Remember Bakit hindi dapat naka-block ang user request habang nagse-send ng email? Kasi ang email sending ay slow I/O operation — pwedeng 1-5 seconds. Kung naka-block ang user, baka mag-timeout o umalis na lang sila.
