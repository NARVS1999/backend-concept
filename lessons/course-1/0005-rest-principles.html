Phase 2: API Design — Lesson 1 of 4

REST Principles & Best Practices

Paano mag-design ng APIs na hindi lang "gumagana" kundi maintainable at scalable.

Lesson Goal Maunawaan ang REST architectural style, proper resource naming, HTTP verbs, at status codes.

Ano ang REST?

Ang REST (Representational State Transfer) ay isang architectural style para sa designing networked applications. Hindi ito protocol o standard — it's a set of constraints.

Key Principles

  • Stateless — Bawat request ay dapat mag-isa, walang client context na naka-store sa server
  • Resource-based — Lahat ay resource (users, orders, products)
  • Uniform Interface — Consistent na paraan ng pag-interact sa resources

Resource Naming

Gumamit ng plural nouns, hindi verbs:

GET    /users        → List all users
POST   /users        → Create a user
GET    /users/{id}   → Get one user
PUT    /users/{id}   → Update entire user
PATCH  /users/{id}   → Partially update user
DELETE /users/{id}   → Delete a user

HTTP Verbs at Status Codes

VerbPurposeSuccess Code
GETRead a resource200 OK
POSTCreate a resource201 Created
PUTReplace a resource200 OK
PATCHPartial update200 OK
DELETERemove a resource204 No Content
PUT vs PATCH PUT = replace the entire resource. PATCH = update only the fields sent. Gamitin ang PATCH para sa partial updates para iwasan ang unnecessary data transfer.
