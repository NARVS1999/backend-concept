Caching Fundamentals

Paano pabilisin ang application mo sa pamamagitan ng pag-store ng frequently-access na data sa mabilis na storage layer.

Lesson Goal Maunawaan ang mga common caching patterns — cache-aside, write-through, at write-behind — at kung kelan gagamitin ang bawat isa.

Ano ang Caching?

Ang caching ay ang pag-store ng kopya ng data sa isang fast storage layer (usually in-memory, like Redis o Memcached) para hindi na kailanganing i-query ang slower primary database sa bawat request.

Caching Patterns

1. Cache-Aside (Lazy Loading)

1. Check kung nasa cache
2. Kung wala (cache miss): query DB, i-store sa cache, return
3. Kung meron (cache hit): return directly from cache
  • Pros: Efficient for read-heavy workloads
  • Cons: May cache miss penalty — unang request ay mabagal
  • Pwedeng mag-serve ng stale data kung hindi i-invalidate

2. Write-Through

  • Data ay sinusulat sa cache at DB nang sabay
  • Pros: Laging fresh ang cache data
  • Cons: Mas mabagal ang writes (doble ang sinusulatan)

3. Write-Behind (Write-Back)

  • Data ay sinusulat sa cache muna, tapos asynchronously sa DB
  • Pros: Napakabilis ng writes
  • Cons: Pwedeng mawala ang data kung mag-crash ang cache bago ma-sync sa DB

Mini-Project: Redis Caching

Mag-set up ng Redis, i-cache ang isang expensive database query, i-measure ang performance improvement.

Summary

  • Cache-aside: DB muna pag miss, saka i-cache — common at efficient
  • Write-through: laging fresh, pero mas mabagal writes
  • Write-behind: super fast writes, pero may data loss risk
