Project Structure Setup

Matutunan kung paano i-set up ang Laravel API-only backend at Next.js frontend — monorepo vs separate repos, at paano mag-test gamit ang health-check endpoint.

Lesson Goal Sa lesson na ito, magagawa mong i-set up ang buong project structure para sa Laravel API backend at Next.js frontend, at i-test ang setup gamit ang health-check endpoint.

Laravel API-Only Setup

Para sa ating Roxy project, gagamitin natin ang Laravel bilang pure API backend — walang Blade templates, walang frontend views. Ang Laravel ang bahala sa data at business logic, ang Next.js naman ang bahala sa UI.

I-set up ang Laravel gamit ang --api flag:

# Create Laravel API project
composer create-project laravel/laravel roxy-api --api

# Navigate to project
cd roxy-api

# Check if it works
php artisan serve
# API runs at http://127.0.0.1:8000/api

Ang difference ng --api vs normal Laravel:

  • No web.php routes — Only api.php routes file
  • Stateless by default — No session middleware, no CSRF token
  • JSON responses only — No Blade views, no redirects
  • Throttle middleware — API rate limiting out of the box

Monorepo vs Separate Repos

Ito ang dalawang options para i-organize ang Laravel at Next.js projects:

Option A: Separate Repos (Recommended for MVP)

# Separate folders sa iyong machine
projects/
├── roxy-api/        ← Laravel API (separate git repo)
└── roxy-web/        ← Next.js frontend (separate git repo)

# Pros:
✅ Simple — hindi magugulo ang git history
✅ Independent deployment — pwede mag-deploy ng backend nang hindi naapektuhan ang frontend
✅ Clear ownership — alam mo kung saan ang backend at frontend code

# Cons:
❌ Manual sync — kailangan mong i-update ang API URL sa .env kapag nagbago
❌ No shared types — kailangan mong i-duplicate ang TypeScript types

Option B: Monorepo (Recommended for scale)

# Single git repo
roxy/
├── apps/
│   ├── api/         ← Laravel API
│   └── web/         ← Next.js frontend
├── packages/
│   └── shared/      ← Shared types, utilities
├── package.json     ← Root package.json
└── README.md

# Pros:
✅ Single git repo — easy to manage
✅ Shared types — pwede mag-share ng TypeScript interfaces
✅ Atomic commits — isang commit para sa backend at frontend change
✅ Better DX — pwede mong i-run ang dalawa sa iisang command

# Cons:
❌ Complex setup — kailangan ng workspace tool (turborepo, nx)
❌ Harder to deploy — kailangan ng monorepo-aware CI/CD
❌ Steeper learning curve

Para sa MVP, gamitin ang separate repos. Mas simple, mas mabilis i-set up, at hindi ka ma-overwhelm. Pwede kang mag-monorepo later kapag lumaki na ang project.

Health-Check Endpoint

Pagkatapos mong i-set up ang dalawang projects, i-test mo agad gamit ang health-check endpoint. Ito ang paraan para malaman kung tama ang setup.

Laravel API health-check:

// routes/api.php
use Illuminate\Support\Facades\Route;

Route::get('/health', function () {
    return response()->json([
        'status' => 'ok',
        'timestamp' => now()->toISOString(),
        'services' => [
            'database' => DB::connection()->getPdo() ? 'connected' : 'disconnected',
            'cache' => Cache::store('default')->getStore() ? 'connected' : 'disconnected',
        ]
    ]);
});

Test the API:

# Run Laravel
php artisan serve

# Test health check
curl http://127.0.0.1:8000/api/health

# Expected response:
# {
#   "status": "ok",
#   "timestamp": "2025-01-15T10:30:00.000000Z",
#   "services": {
#     "database": "connected",
#     "cache": "connected"
#   }
# }

Next.js API client:

// src/lib/api.ts
const API_BASE = process.env.NEXT_PUBLIC_API_URL || 'http://127.0.0.1:8000/api';

export async function healthCheck() {
  const res = await fetch(`${API_BASE}/health`);
  return res.json();
}

// src/app/page.tsx
import { healthCheck } from '@/lib/api';

export default async function Home() {
  const health = await healthCheck();
  
  return (
    <main>
      <h1>Roxy Store</h1>
      <p>API Status: {health.status}</p>
      <p>Database: {health.services.database}</p>
    </main>
  );
}

Quiz

Summary

  • Ang --api flag sa Laravel ay nag-c-create ng API-only project — walang Blade views, stateless, JSON responses only.
  • Ang Next.js App Router ang gagamitin sa frontend — may src/ directory, TypeScript, at App Router structure.
  • Para sa MVP, separate repos ang mas simple at recommended — mag-monorepo ka na lang later kapag lumaki na ang project.
  • Ang health-check endpoint ang first test para malaman kung tama ang setup mo — dapat mag-return ng "ok" status at database connection.
Interview Angle "How do you structure your full-stack projects?" — Nagse-separate ako ng Laravel API at Next.js frontend repos. Ang Laravel ay API-only (walang Blade), ang Next.js naman ay sa UI. Nagse-set ako ng health-check endpoint para i-verify agad na tama ang setup at connected ang database.
