Error Handling End-to-End

Paano ba mag-handle ng errors nang maayos mula sa Laravel API hanggang sa Next.js frontend?

Lesson Goal Sa lesson na ito, magagawa mong i-standardize ang error responses sa Laravel API, i-consume at i-display ang mga errors sa Next.js gamit ang toast notifications at inline errors, at ma-implement ang proper exception handling.

Standardizing Error Responses sa Laravel

Ang pinaka-importanteng bagay sa error handling ay consistency. Ang lahat ng error responses mula sa API ay dapat sumusunod sa iisang JSON structure. Ito ay nagbibigay ng predictable format para sa frontend developers.

Gumawa ng base exception handler na nagfo-format ng errors nang consistent:

// app/Exceptions/Handler.php
public function register(): void
{
    $this->renderable(function (HttpException $e, $request) {
        if ($request->expectsJson()) {
            return response()->json([
                'success' => false,
                'message' => $e->getMessage(),
                'errors' => $this->formatErrors($e),
            ], $e->getStatusCode());
        }
    });
}

private function formatErrors(HttpException $e): array
{
    $errors = [];
    if ($e instanceof ValidationException) {
        $errors = $e->errors();
    }
    return $errors;
}

Para sa validation errors, ang Laravel ay may built-in na pag-format, pero pwede mo ring i-customize:

// app/Exceptions/Handler.php
public function register(): void
{
    $this->renderable(function (ValidationException $e, $request) {
        if ($request->expectsJson()) {
            return response()->json([
                'success' => false,
                'message' => 'Validation failed',
                'errors' => $e->errors(),
            ], 422);
        }
    });

    $this->renderable(function (ModelNotFoundException $e, $request) {
        if ($request->expectsJson()) {
            return response()->json([
                'success' => false,
                'message' => 'Resource not found',
                'errors' => [],
            ], 404);
        }
    });

    $this->renderable(function (AuthenticationException $e, $request) {
        if ($request->expectsJson()) {
            return response()->json([
                'success' => false,
                'message' => 'Unauthenticated',
                'errors' => [],
            ], 401);
        }
    });
}

Ang standard JSON response format ay dapat ganito:

// Success response
{
    "success": true,
    "message": "User created successfully",
    "data": { "id": 1, "name": "Juan" }
}

// Error response
{
    "success": false,
    "message": "Validation failed",
    "errors": {
        "email": ["The email field is required."],
        "password": ["The password must be at least 8 characters."]
    }
}

Handling API Errors sa Next.js

Sa Next.js, gumawa ng centralized error handling function para sa API calls. Ito ay nagbibigay ng consistent na paraan para i-handle ang lahat ng errors:

// lib/api.js
export async function apiCall(endpoint, options = {}) {
  const baseUrl = process.env.NEXT_PUBLIC_API_URL;
  const url = `${baseUrl}${endpoint}`;

  try {
    const response = await fetch(url, {
      ...options,
      headers: {
        'Content-Type': 'application/json',
        'Accept': 'application/json',
        ...options.headers,
      },
    });

    const data = await response.json();

    if (!response.ok) {
      throw {
        status: response.status,
        message: data.message || 'Something went wrong',
        errors: data.errors || {},
      };
    }

    return data;
  } catch (error) {
    if (error.status) {
      throw error;
    }
    throw {
      status: 500,
      message: 'Network error. Please try again.',
      errors: {},
    };
  }
}

Pagkatapos, gamitin ang function na ito sa components:

// pages/login.js
import { useState } from 'react';
import { apiCall } from '../lib/api';
import toast from 'react-hot-toast';

export default function Login() {
  const [errors, setErrors] = useState({});
  const [loading, setLoading] = useState(false);

  const handleSubmit = async (e) => {
    e.preventDefault();
    setErrors({});
    setLoading(true);

    try {
      const data = await apiCall('/login', {
        method: 'POST',
        body: JSON.stringify({ email, password }),
      });
      toast.success('Login successful!');
      router.push('/dashboard');
    } catch (error) {
      if (error.status === 422) {
        setErrors(error.errors);
      } else {
        toast.error(error.message);
      }
    } finally {
      setLoading(false);
    }
  };
}

Displaying Errors sa Frontend

May dalawang pangunahing paraan para i-display ang errors sa frontend: toast notifications at inline errors.

Toast Notifications: Para sa general errors (network errors, server errors). Gamit ang react-hot-toast o sonner:

import toast from 'react-hot-toast';

// Success
toast.success('Item saved!');

// Error
toast.error('Failed to save item');

// Warning
toast.error('Session expired. Please login again.');

Inline Errors: Para sa validation errors. I-display ang error message sa tabi ng form field:

// components/FormField.js
export function FormField({ label, name, errors }) {
  return (
    <div className="form-field">
      <label htmlFor={name}>{label}</label>
      <input id={name} name={name} />
      {errors[name] && (
        <span className="error-message">
          {errors[name][0]}
        </span>
      )}
    </div>
  );
}

// Usage
<FormField
  label="Email"
  name="email"
  errors={errors}
/>

Ang pattern na ito ay nagbibigay ng malinaw na feedback sa user. Ang toast ay para sa transient messages (lalabas at mawawala), habang ang inline errors ay para sa persistent validation feedback.

Practical: Implement End-to-End Error Handling

Step 1: Sa Laravel, i-modify ang app/Exceptions/Handler.php para i-format ang errors sa JSON format. I-handle ang ValidationException, ModelNotFoundException, at AuthenticationException.

Step 2: Gumawa ng lib/api.js sa Next.js na may centralized apiCall function. Siguraduhin na ang function ay nagpa-parse ng JSON at nag-thrown ng structured errors.

Step 3: I-install ang react-hot-toast sa Next.js: npm install react-hot-toast. I-add ang <Toaster /> component sa root layout.

Step 4: Gumawa ng form (halimbawa: login o registration form) na gumagamit ng apiCall function. I-handle ang 422 errors para sa validation at other errors para sa toast.

Step 5: I-display ang validation errors inline sa form fields. Gumawa ng reusable FormField component na tumatanggap ng errors prop.

Step 6: I-test ang error handling. Mag-send ng invalid data sa API at tingnan kung tama ang pag-display ng errors sa frontend.
