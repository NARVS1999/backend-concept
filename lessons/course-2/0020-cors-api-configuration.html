CORS & API Configuration

Paano ba nagko-connect ang Laravel API at Next.js frontend nang hindi nagkakaroon ng CORS errors?

Lesson Goal Sa lesson na ito, magagawa mong i-configure nang tama ang CORS settings sa Laravel para tumanggap ng requests mula sa Next.js frontend, at malalaman mo kung bakit nagkakaroon ng CORS errors.

Ano ang CORS?

Cross-Origin Resource Sharing (CORS) ay isang security mechanism ng browsers. Kapag ang isang web page sa http://localhost:3000 (Next.js) ay nag-request sa API sa http://localhost:8000 (Laravel), ibang "origin" yan. Ang browser, by default, nagbabawal sa cross-origin requests para maiwasan ang security attacks tulad ng CSRF.

Ang CORS ay nagbibigay ng paraan para sabihin ng server kung aling origins ang allowed na mag-request. Kapag hindi configured ang CORS, makakakuha ka ng error sa browser console na parang:

Access to XMLHttpRequest at 'http://localhost:8000/api/users' from origin 'http://localhost:3000' has been blocked by CORS policy.

CORS Configuration sa Laravel

Ang CORS settings sa Laravel ay nasa config/cors.php. Narito ang mga importanteng settings:

// config/cors.php
return [
    'paths' => ['api/*', 'sanctum/csrf-cookie'],

    'allowed_methods' => ['*'],

    'allowed_origins' => ['http://localhost:3000'],

    'allowed_origins_patterns' => [],

    'allowed_headers' => ['*'],

    'exposed_headers' => [],

    'max_age' => 0,

    'supports_credentials' => false,
];

Ang allowed_origins ay ang pinaka-importanteng setting. Dito mo ilalagay ang URL ng iyong Next.js frontend. Kapag nasa development ka, ilagay mo ang http://localhost:3000. Kapag naman production na, palitan mo ng production domain.

Ang paths naman ay ang mga API routes na a-apply-an ng CORS policy. Ang api/* ay lahat ng routes na nasa /api/ prefix.

Kung gumagamit ka ng Sanctum for authentication, kailangan mo ring isama ang sanctum/csrf-cookie path para sa CSRF token fetching.

Debugging Common CORS Errors

Ang CORS errors ay madalas mangyari kapag may mali sa configuration. Narito ang mga common na issues:

1. Origin not allowed: I-check ang allowed_origins sa config/cors.php. Siguraduhin na tama ang URL — kasama ang protocol (http:// o https://) at port number.

2. Method not allowed: Kung nagse-send ka ng POST request pero ang allowed_methods ay GET lang, mag-eerror. Sa development, pwedeng gamitin ang ['*'] para i-allow lahat.

3. Headers not allowed: Kapag nagse-send ka ng custom headers (halimbawa: Authorization: Bearer token), kailangan mo ring i-allow ang headers sa CORS config.

4. Sanctum + SPA mode: Kung gumagamit ka ng Sanctum SPA authentication, kailangan mong i-enable ang supports_credentials at ilagay ang domain sa stateful domains sa config/sanctum.php:

// config/sanctum.php
'stateful' => explode(',', env('SANCTUM_STATEFUL_DOMAINS', sprintf(
    '%s%s',
    'localhost,localhost:3000,127.0.0.1,127.0.0.1:8000,::1',
    env('APP_URL') ? ','.parse_url(env('APP_URL'), PHP_URL_HOST) : ''
))),

Practical: Configure CORS for Laravel + Next.js

Sundin ang mga ito para ma-configure ang CORS ng iyong project:

Step 1: Buksan ang config/cors.php sa Laravel project.

Step 2: I-set ang allowed_origins sa ['http://localhost:3000'] para sa development.

Step 3: I-set ang allowed_methods sa ['*'] o partikular na methods: ['GET', 'POST', 'PUT', 'DELETE', 'OPTIONS'].

Step 4: I-set ang allowed_headers sa ['*'] para i-allow lahat ng headers.

Step 5: Clear ang config cache: php artisan config:clear.

Step 6: Test gamit ang Next.js frontend. Gumawa ng fetch request mula sa localhost:3000 papunta sa localhost:8000/api/test. Dapat walang CORS error sa browser console.

Para sa production, palitan ang allowed_origins ng production domain ng frontend, halimbawa: ['https://yourdomain.com']. Huwag gamitin ang ['*'] sa production dahil security risk yan.
