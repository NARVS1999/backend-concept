Phase 6: Business/Product Considerations — Lesson 2 of 3

Analytics & User Behavior

Paano mo malalaman kung paano ginagamit ng users ang app mo? Setup analytics at i-track ang user behavior.

Lesson Goal Sa lesson na ito, magagawa mong i-setup ang analytics (Plausible o PostHog), i-track ang key metrics (signups, conversions, drop-offs), i-implement ang custom event tracking, at basahin ang data para sa product decisions.

Bakit Kailangan ng Analytics?

Kapag na-deploy na ang app mo, kailangan mong malaman kung paano ito ginagamit ng users. Walang analytics = walang data para sa decisions. Hindi mo malalaman kung alin ang nagwo-work at kung alin ang kailangang baguhin.

Mga tanong na masasagot ng analytics:

  • Ilan ang nag-signup per day/week/month? — Ito ang growth rate mo.
  • Saan nag-drop-off ang users? — Saan sila umaalis bago mag-complete ng action?
  • Anong features ang most used? — Alin ang nagbibigay ng value sa users?
  • Anong device/browser ang gamit? — Para sa compatibility testing.
  • Saan nanggagaling ang users? — Organic search, social media, o direct?
  • Ano ang conversion rate? — Ilan ang nag-signup sa ilalim ng total visitors?

Ano ang dapat i-track:

  • Signups — Ilang bago nag-create ng account per period.
  • Logins — Ilang users ang bumabalik (returning users).
  • Conversions — Ilan ang nag-upgrade sa paid plan, nag-purchase, o nag-complete ng key action.
  • Drop-off points — Saan umaalis ang users sa funnel (signup -> onboarding -> first action -> payment).
  • Feature usage — Aling features ang most/least used.

Plausible — Privacy-First Analytics

Ang Plausible ay lightweight, privacy-friendly na analytics alternative sa Google Analytics. Hindi ito gumagamit ng cookies, hindi nagta-track ng personal data, at GDPR/CCPA compliant agad. Para sa Laravel + Next.js app, ito ang simplest option.

Setup sa Next.js:

# I-install ang Plausible client
npm install @plausible-analytics/tracker

# Sa app/layout.tsx, i-add ang Plausible script
import PlausibleProvider from 'next-plausible'

export default function RootLayout({ children }) {
  return (
    <PlausibleProvider domain="roxy.com">
      {children}
    </PlausibleProvider>
  );
}

Custom event tracking sa Next.js:

// app/components/SignupForm.tsx
'use client'

import { plausible } from 'next-plausible'

export default function SignupForm() {
  const handleSubmit = async (e) => {
    e.preventDefault()

    // I-track ang signup attempt
    plausible('Signup Attempt', {
      props: {
        plan: selectedPlan,
        source: window.location.pathname,
      },
    })

    try {
      const res = await fetch('/api/auth/register', {
        method: 'POST',
        body: JSON.stringify(formData),
      })

      if (res.ok) {
        // I-track ang successful signup
        plausible('Signup Success', {
          props: { plan: selectedPlan },
        })
      }
    } catch (error) {
      plausible('Signup Failed', {
        props: { error: error.message },
      })
    }
  }

  return <form onSubmit={handleSubmit}>...</form>
}

Plausible dashboard features:

  • Top pages — Aling pages ang may pinaka-views.
  • Referrers — Saan nanggagaling ang traffic (Google, Twitter, direct).
  • Devices — Desktop vs mobile vs tablet breakdown.
  • Countries — Geographic distribution ng users.
  • Goals — Custom conversions (signups, purchases) na naka-track.

Setup goals sa Plausible dashboard: Pumunta sa Site Settings -> Goals -> Add Goal. I-set ang custom events na na-track mo sa code (hal. "Signup Success", "Payment Completed"). Ito ang magpapakita ng conversion metrics sa dashboard.

PostHog — Product Analytics

Ang PostHog ay mas powerful kaysa sa Plausible — may session recordings, feature flags, A/B testing, at cohort analysis. Para sa apps na kailangan ng deep product insights, ito ang better choice. May self-hosted option para sa full data control.

Setup sa Next.js:

# I-install ang PostHog
npm install posthog-js

# lib/posthog.ts
import posthog from 'posthog-js'

if (typeof window !== 'undefined') {
  posthog.init(process.env.NEXT_PUBLIC_POSTHOG_KEY!, {
    api_host: process.env.NEXT_PUBLIC_POSTHOG_HOST || 'https://app.posthog.com',
    loaded: (ph) => {
      if (process.env.NODE_ENV === 'development') ph.opt_out_capturing()
    },
  })
}

export default posthog

PostHog provider sa app:

// app/providers.tsx
'use client'

import { PostHogProvider } from 'posthog-js/react'
import posthog from '@/lib/posthog'

export default function Providers({ children }) {
  return (
    <PostHogProvider client={posthog}>
      {children}
    </PostHogProvider>
  )
}

Custom event tracking sa PostHog:

// app/dashboard/page.tsx
'use client'

import posthog from '@/lib/posthog'
import { useUser } from '@/lib/auth'

export default function Dashboard() {
  const user = useUser()

  const handleFeatureClick = (featureName) => {
    posthog.capture('feature_clicked', {
      feature: featureName,
      user_plan: user.plan,
      dashboard_section: 'main',
    })
  }

  const handleUpgrade = () => {
    posthog.capture('upgrade_initiated', {
      current_plan: user.plan,
      target_plan: 'pro',
      page: window.location.pathname,
    })
  }

  return (
    <div>
      <button onClick={() => handleFeatureClick('analytics')}>View Analytics</button>
      <button onClick={handleUpgrade}>Upgrade to Pro</button>
    </div>
  )
}

PostHog features na useful:

  • Session recordings — I-record ang actual user sessions para makita kung paano ginagamit ang app (with consent).
  • Feature flags — I-toggle ang features sa live na hindi nagde-deploy. I-release ang new features sa certain users lang.
  • A/B testing — I-compare ang dalawang versions ng feature para malaman kung alin ang mas effective.
  • Funnels — I-visualize ang user journey at makita kung saan nag-drop-off.
  • Cohorts — I-group ang users based sa behavior (e.g., users na nag-login ng 3+ times sa nakaraang linggo).

Custom Event Tracking sa Laravel

Ang Laravel ay may built-in na event system na pwedeng gamitin para sa custom analytics. I-log ang important business events sa database para sa reporting.

Event model at migration:

// migration: create_events_table
Schema::create('events', function (Blueprint $table) {
    $table->id();
    $table->foreignId('user_id')->nullable();
    $table->string('event_name'); // signup, purchase, feature_used
    $table->json('properties')->nullable(); // additional data
    $table->string('ip_address', 45)->nullable();
    $table->string('user_agent')->nullable();
    $table->timestamps();

    $table->index(['event_name', 'created_at']);
});

Event tracking service:

// app/Services/AnalyticsService.php
namespace App\Services;

use App\Models\Event;

class AnalyticsService
{
    public function track(string $eventName, array $properties = []): Event
    {
        return Event::create([
            'user_id' => auth()->id(),
            'event_name' => $eventName,
            'properties' => $properties,
            'ip_address' => request()->ip(),
            'user_agent' => request()->userAgent(),
        ]);
    }

    public function getSignupCount(string $period = 'day'): int
    {
        return Event::where('event_name', 'signup')
            ->where('created_at', '>=', now()->subDay($period === 'day' ? 1 : 7))
            ->count();
    }

    public function getConversionRate(): float
    {
        $visits = Event::where('event_name', 'page_visit')->count();
        $signups = Event::where('event_name', 'signup')->count();

        return $visits > 0 ? ($signups / $visits) * 100 : 0;
    }

    public function getFeatureUsage(): array
    {
        return Event::where('event_name', 'feature_used')
            ->select('properties->feature as feature', \DB::raw('count(*) as total'))
            ->groupBy('feature')
            ->orderByDesc('total')
            ->pluck('total', 'feature')
            ->toArray();
    }
}

Controller usage:

// app/Http/Controllers/Auth/RegisterController.php
use App\Services\AnalyticsService;

class RegisterController extends Controller
{
    public function store(Request $request, AnalyticsService $analytics)
    {
        $user = User::create($validated);

        $analytics->track('signup', [
            'plan' => $request->plan,
            'referral_source' => $request->referrer,
        ]);

        return new UserResource($user);
    }
}

// app/Http/Controllers/AnalyticsController.php
class AnalyticsController extends Controller
{
    public function index(AnalyticsService $analytics)
    {
        return response()->json([
            'signups_today' => $analytics->getSignupCount('day'),
            'signups_this_week' => $analytics->getSignupCount('week'),
            'conversion_rate' => $analytics->getConversionRate(),
            'feature_usage' => $analytics->getFeatureUsage(),
        ]);
    }
}

Reading Analytics Data for Decisions

Hindi sapat na mag-collect ng data — kailangan mong basahin ito at gawing decisions. Ito ang practical framework para sa pag-interpret ng analytics:

Key metrics na dapat mong tingnan:

  • Daily Active Users (DAU) / Monthly Active Users (MAU) — Ito ang health metric ng app mo. Kung bumababa ang DAU, may problema sa retention.
  • Conversion Funnel — Signup -> Onboarding -> First Action -> Payment. Kung mataas ang drop-off sa onboarding, i-simplify ang flow.
  • Feature Adoption — Aling features ang ginagamit ng users? Kung hindi ginagamit ang isang feature, baka hindi ito valuable o hindi lang alam ng users.
  • Retention Rate — Ilan ang bumabalik after 1 day, 7 days, 30 days? Ang target ay 40%+ sa day 1 at 10%+ sa day 30.

Example decisions mula sa data:

// Kung ang signup-to-onboarding drop-off ay 70%:
// -> I-simplify ang onboarding flow (remove unnecessary steps)
// -> I-add ang progress indicator
// -> I-send ang welcome email na may step-by-step guide

// Kung ang mobile users ay 60% pero mobile conversion ay mababa:
// -> I-optimize ang mobile UX
// -> I-check ang mobile-specific bugs
// -> I-simplify ang mobile forms

// Kung ang DAU ay bumababa ng 10% per week:
// -> I-improve ang email re-engagement campaign
// -> I-add ang push notifications
// -> I-check kung may UX issues na nag-cause ng churn

Analytics dashboard sa Next.js:

// app/dashboard/analytics/page.tsx
'use client'

import { useEffect, useState } from 'react'

export default function AnalyticsDashboard() {
  const [data, setData] = useState(null)

  useEffect(() => {
    fetch('/api/analytics')
      .then(res => res.json())
      .then(setData)
  }, [])

  if (!data) return <div>Loading...</div>

  return (
    <div className="analytics-grid">
      <MetricCard title="Signups Today" value={data.signups_today} />
      <MetricCard title="Conversion Rate" value={`${data.conversion_rate.toFixed(1)}%`} />
      <FeatureUsageChart data={data.feature_usage} />
      <ConversionFunnel data={data.funnel} />
    </div>
  )
}

Practical: Set Up Analytics

Step 1: Pumili ng analytics platform — Plausible para sa simple page views at goals, o PostHog para sa deep product analytics. Gumawa ng account at kunin ang API key.

Step 2: I-integrate sa Next.js — i-install ang SDK, i-add ang provider sa root layout, at i-configure ang domain/API key sa environment variables.

Step 3: I-track ang key events — signup, login, feature usage, payment. Gumamit ng descriptive event names at i-add ang relevant props (plan type, source, feature name).

Step 4: Sa Laravel, gumawa ng AnalyticsService na naglo-log ng events sa database. I-use ito sa controllers para sa important business events (signup, purchase, feature access).

Step 5: Gumawa ng simple analytics dashboard sa Next.js — metric cards para sa signups, conversion rate, at feature usage. I-fetch ang data mula sa Laravel API.

Step 6: I-review ang analytics after 1-2 weeks. Hanapin ang patterns — saan nag-drop-off ang users? Anong features ang most used? Gumawa ng decisions base sa data.
