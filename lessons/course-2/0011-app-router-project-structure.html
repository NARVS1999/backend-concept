App Router Basics & Project Structure

Alamin kung paano gamitin ang Next.js App Router at i-set up ang tamang project structure para sa Laravel + Next.js project.

Lesson Goal Sa lesson na ito, magagawa mong i-set up ang Next.js project gamit ang App Router at maunawaan kung kailan gagamitin ang server components vs client components.

Ano ang App Router?

Ang App Router ay ang bagong routing system ng Next.js 13+ na nasa app/ folder. Ito ang default na gamit ngayon at mas flexible kaysa sa lumang Pages Router. Sa App Router, ang bawat folder sa app/ ay isang route — at ang page.js file sa loob ang nagde-determine kung ano ang render sa route na yun.

Halimbawa ng folder structure:

app/
├── layout.js          ← Root layout (naka-wrap sa lahat ng pages)
├── page.js            ← Home page (/)
├── listings/
│   ├── page.js        ← /listings
│   └── [id]/
│       └── page.js    ← /listings/123
├── dashboard/
│   ├── layout.js      ← Dashboard-specific layout
│   └── page.js        ← /dashboard
└── login/
    └── page.js        ← /login

Ang bentahe ng App Router ay built-in na ang server rendering, loading states, at error handling per route segment. Hindi mo na kailangan ng separate na setup para dito.

Server Components vs Client Components

Isa sa pinakamahalagang konsepto sa Next.js App Router ay ang pagkakaiba ng server at client components. Sa App Router, lahat ng components ay server components by default — ibig sabihin, nagre-render sila sa server at hindi nagse-send ng JavaScript sa client.

Server Components ang gamitin mo kapag:

  • Nagfe-fetch ka ng data mula sa Laravel API
  • Access ka sa database directly (though hindi to ang case sa ating Laravel setup)
  • Hindi mo kailangan ng user interaction (clicks, forms, state)
  • Gusto mo ng mas mabilis na initial page load
// app/listings/page.js — Server Component (default)
async function ListingsPage() {
  const res = await fetch('http://localhost:8000/api/listings');
  const listings = await res.json();

  return (
    <div>
      <h1>All Listings</h1>
      {listings.map(listing => (
        <ListingCard key={listing.id} listing={listing} />
      ))}
    </div>
  );
}

export default ListingsPage;

Client Components naman ang kailangan mo kapag:

  • May user interaction — clicks, forms, inputs
  • Gumagamit ng useState, useEffect, o ibang React hooks
  • Gumagamit ng browser APIs (localStorage, window, etc.)
  • Gumagamit ng event handlers (onClick, onChange)

I-mark mo lang ang component bilang client sa pamamagitan ng 'use client' directive sa itaas ng file:

'use client';

import { useState } from 'react';

export default function SearchBar() {
  const [query, setQuery] = useState('');

  return (
    <input
      type="text"
      value={query}
      onChange={(e) => setQuery(e.target.value)}
      placeholder="Search listings..."
    />
  );
}

Rule of thumb: I-push ang 'use client' hanggang sa pinaka-kailangan lang. Hindi mo kailangan gawin ang entire page bilang client — pwede mong gawin client lang ang isang interactive na component at i-keep ang parent server component.

Project Structure para sa Laravel + Next.js

Para sa ating Roxy project, ganito ang recommended na structure sa loob ng Next.js app:

app/
├── (auth)/
│   ├── login/page.js
│   └── register/page.js
├── (dashboard)/
│   ├── layout.js         ← Dashboard layout with sidebar
│   ├── page.js           ← Dashboard home
│   ├── listings/
│   │   ├── page.js       ← Listing index
│   │   ├── new/page.js   ← Create listing
│   │   └── [id]/
│   │       ├── page.js   ← View listing
│   │       └── edit/page.js ← Edit listing
│   └── profile/
│       └── page.js
├── layout.js             ← Root layout
├── page.js               ← Public landing page
└── globals.css

lib/
├── api.js                ← Laravel API helper functions
├── auth.js               ← Auth utilities
└── utils.js              ← Shared utilities

components/
├── ui/                   ← Reusable UI components
│   ├── Button.js
│   ├── Input.js
│   └── Modal.js
├── listings/
│   ├── ListingCard.js
│   └── ListingForm.js
└── layout/
    ├── Sidebar.js
    └── Header.js

Ang (auth) at (dashboard) ay route groups — hindi sila nagdadagdag sa URL path. Ibig sabihin, ang (auth)/login/page.js ay nasa /login lang, hindi /auth/login. Ang gamit nila ay para mag-organize ng shared layouts.

Setting Up ang Laravel API Helper

Lumikha ng lib/api.js para i-centralize ang lahat ng API calls sa Laravel:

// lib/api.js
const API_BASE = process.env.NEXT_PUBLIC_API_URL || 'http://localhost:8000/api';

async function fetchAPI(endpoint, options = {}) {
  const url = `${API_BASE}${endpoint}`;

  const res = await fetch(url, {
    ...options,
    headers: {
      'Content-Type': 'application/json',
      'Accept': 'application/json',
      ...options.headers,
    },
  });

  if (!res.ok) {
    const error = await res.json().catch(() => ({ message: 'Request failed' }));
    throw new Error(error.message || `API error: ${res.status}`);
  }

  return res.json();
}

export const api = {
  get: (endpoint) => fetchAPI(endpoint),
  post: (endpoint, data) => fetchAPI(endpoint, {
    method: 'POST',
    body: JSON.stringify(data),
  }),
  put: (endpoint, data) => fetchAPI(endpoint, {
    method: 'PUT',
    body: JSON.stringify(data),
  }),
  delete: (endpoint) => fetchAPI(endpoint, {
    method: 'DELETE',
  }),
};

export default api;

Ito ang magiging foundation ng lahat mong API interactions. Sa next lessons, gagamitin natin ang api.get(), api.post(), etc. para makipag-communicate sa Laravel backend.

Quiz

Summary

  • Ang App Router ay nasa app/ folder — bawat folder ay route, at page.js ang nagre-render sa route na yun.
  • Server components ang default — gamitin ang 'use client' lang kapag kailangan ng interaction, hooks, o browser APIs.
  • I-structure ang project gamit ang route groups (auth), (dashboard) para malinis ang organization.
  • Lumikha ng centralized API helper sa lib/api.js para lahat ng Laravel API calls ay dadaan sa iisang place.
