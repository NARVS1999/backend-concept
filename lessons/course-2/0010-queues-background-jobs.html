Queues & Background Jobs

Matutunan kung kailan gamitin ang Laravel queues para sa background processing, paano mag-setup ng queue worker, at paano mag-implement ng job chaining.

Lesson Goal Sa lesson na ito, magagawa mong i-move ang isang synchronous operation sa isang queued job para mas mabilis ang response time ng API.

Kailan Gamitin ang Queues?

Ang queues ay ginagamit para i-move ang heavy o time-consuming na operations sa background. Ito ay nagpo-improve ng user experience dahil hindi na naghihintay ang user sa matagal na operations.

Mga Situations na Kailangan ng Queues:

  • Email sending — Ang pagpadala ng email ay maaaring mag-take ng ilang segundo. I-queue ito para hindi mag-wait ang user.
  • Notifications — Push notifications, SMS, at iba pang notifications.
  • Image processing — Resize, crop, o watermark ng images.
  • Report generation — Pag-gawa ng PDF reports o CSV exports.
  • Heavy computations — Data analysis, machine learning predictions.
  • Third-party API calls — Pag-call sa external APIs na maaaring mag-fail o mag-timeout.
// Synchronous (bad - user waits)
public function store(PostRequest $request)
{
    $post = Post::create($request->validated());
    
    // This takes 2-3 seconds!
    Mail::to($request->user())->send(new PostPublished($post));
    
    return new PostResource($post);
}

// Queued (good - user doesn't wait)
public function store(PostRequest $request)
{
    $post = Post::create($request->validated());
    
    // This is instant - sent to queue
    Mail::to($request->user())->queue(new PostPublished($post));
    
    return new PostResource($post);
}

Queue Configuration

I-configure ang queues sa config/queue.php:

// config/queue.php
'connections' => [
    'sync' => [
        'driver' => 'sync',
    ],

    'database' => [
        'driver' => 'database',
        'table' => 'jobs',
        'queue' => 'default',
        'retry_after' => 90,
    ],

    'redis' => [
        'driver' => 'redis',
        'connection' => 'default',
        'queue' => 'default',
        'retry_after' => 90,
        'block_for' => null,
    ],

    'sqs' => [
        'driver' => 'sqs',
        'key' => env('AWS_ACCESS_KEY_ID'),
        'secret' => env('AWS_SECRET_ACCESS_KEY'),
        'prefix' => env('SQS_PREFIX'),
        'queue' => env('SQS_QUEUE'),
        'region' => env('AWS_DEFAULT_REGION'),
    ],
],

'default' => env('QUEUE_CONNECTION', 'sync'),

Queue Drivers:

  • sync — Synchronous execution (no queue). Default para sa development.
  • database — Database table as queue. Simple pero hindi scalable.
  • redis — Redis as queue. Fast at scalable. Recommended para sa production.
  • sqs — Amazon SQS. Managed service ng AWS.

Creating Jobs

Gumawa ng jobs para sa background processing:

// Step 1: Create job class
php artisan make:job SendPostPublishedEmail

// Step 2: Implement the job
class SendPostPublishedEmail implements ShouldQueue
{
    use Dispatchable, InteractsWithQueue, Queueable, SerializesModels;

    public function __construct(
        public Post $post,
        public User $user
    ) {}

    public function handle(Mailer $mailer): void
    {
        // This is executed in the background
        $mailer->to($this->user->email)
            ->send(new PostPublished($this->post));
    }

    public function failed(Throwable $exception): void
    {
        // Handle failed job
        Log::error('Failed to send email: ' . $exception->getMessage());
    }
}

// Step 3: Dispatch the job
class PostController extends Controller
{
    public function store(PostRequest $request)
    {
        $post = auth()->user()->posts()->create($request->validated());
        
        // Dispatch job to queue
        SendPostPublishedEmail::dispatch($post, auth()->user());
        
        return new PostResource($post);
    }
}

Job Methods:

  • __construct() — I-setup ang job data. Ang data dito ay i-serialize sa database.
  • handle() — I-execute ang job logic. Ito ang "work" ng job.
  • failed() — I-handle ang failed job. Pwede mong i-log o i-notify.
  • middleware() — I-define ang job middleware (e.g., withoutOverlapping, onConnection).

Job Chaining & Advanced Features

Pwede mong i-chain ang jobs para sa sequential processing:

// Job chaining
use Illuminate\Support\Facades\Bus;

Bus::chain([
    new ProcessImage($image),
    new ResizeImage($image, 800, 600),
    new UploadToS3($image),
    new NotifyUser($user, 'Image processed successfully'),
])->onConnection('redis')->onQueue('high')->dispatch();

// Job chaining with callbacks
Bus::chain([
    new ProcessPayment($order),
    new SendReceipt($order),
    new UpdateInventory($order),
])->then(function () {
    // All jobs completed successfully
    Log::info('Order processed successfully');
})->catch(function (Throwable $e) {
    // Something failed
    Log::error('Order processing failed: ' . $e->getMessage());
})->finally(function () {
    // Always runs
    Log::info('Order processing chain completed');
})->dispatch();

Job Middleware:

class ProcessImage implements ShouldQueue
{
    use Dispatchable, InteractsWithQueue, Queueable, SerializesModels;

    public function __construct(public Image $image) {}

    public function middleware(): array
    {
        return [
            new WithoutOverlapping('process-image'),
            new ThrottlesExceptions(10, 60), // 10 exceptions per minute
        ];
    }

    public function handle(): void
    {
        // Process image...
    }
}

Queue Worker Setup:

// Start queue worker
php artisan queue:work

// Start with specific connection and queue
php artisan queue:work redis --queue=high,default,low

// Start with memory limit
php artisan queue:work --memory=512

// Start with timeout
php artisan queue:work --timeout=60

// Supervisor configuration (production)
// /etc/supervisor/conf.d/laravel-worker.conf
[program:laravel-worker]
process_name=%(program_name)s_%(process_num)02d
command=php /path/to/artisan queue:work redis --sleep=3 --tries=3 --max-time=3600
autostart=true
autorestart=true
stopasgroup=true
killasgroup=true
user=www-data
numprocs=8
redirect_stderr=true
stdout_logfile=/path/to/storage/logs/worker.log
stopwaitsecs=3600

Quiz

Summary

  • Ang queues ay ginagamit para i-move ang heavy operations sa background — nagpo-improve ng user experience.
  • Ang sync driver ay synchronous (no queue), habang ang database at redis ay actual queues.
  • Ang jobs ay classes na nag-implement ng ShouldQueue interface — nagpo-provide ng handle() method para sa work.
  • Ang job chaining ay nagpo-possibility ng sequential processing — halimbawa: process → resize → upload → notify.
Interview Angle "When would you use queues in Laravel?" — Gumagamit ako ng queues para sa email sending, notifications, image processing, report generation, at heavy computations. I-move ko ito sa background para hindi mag-wait ang user at mas mabilis ang API response time.
