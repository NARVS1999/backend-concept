Authorization (Policies & Gates)

Matutunan kung paano i-protect ang iyong endpoints gamit ang Laravel Policies at Gates para sa role-based at ownership-based authorization.

Lesson Goal Sa lesson na ito, magagawa mong i-implement ang isang Policy para sa resource — halimbawa, ang user ay pwedeng mag-edit o mag-delete lamang ng sarili niyang posts.

Policies vs Gates

Ang authorization ay ang proseso ng pag-determine kung ang authenticated user ay may permission na gawin ang isang action. Sa Laravel, dalawang approach ang ginagamit:

  • Policies — Dedicated classes na nag-handle ng authorization logic para sa isang specific model. Ito ay organized at testable.
  • Gates — Simple closures na nag-de-determine ng authorization. Ito ay mas flexible pero hindi organized.
// Policy - organized, testable
// app/Policies/PostPolicy.php
class PostPolicy
{
    public function viewAny(User $user)
    {
        return true; // Lahat makakakita ng posts
    }

    public function view(User $user, Post $post)
    {
        return true; // Lahat makakakita ng individual post
    }

    public function create(User $user)
    {
        return true; // Lahat pwedeng gumawa ng post
    }

    public function update(User $user, Post $post)
    {
        return $user->id === $post->user_id; // Only owner can update
    }

    public function delete(User $user, Post $post)
    {
        return $user->id === $post->user_id; // Only owner can delete
    }

    public function forceDelete(User $user, Post $post)
    {
        return $user->isAdmin(); // Only admin can force delete
    }
}
// Gate - flexible, inline
use Illuminate\Support\Facades\Gate;

Gate::define('update-post', function (User $user, Post $post) {
    return $user->id === $post->user_id;
});

Gate::define('delete-post', function (User $user, Post $post) {
    return $user->id === $post->user_id;
});

Gate::define('admin-only', function (User $user) {
    return $user->isAdmin();
});

Registering Policies

Ang policies ay kailangan i-register para ma-detect ng Laravel. Ito ay auto-registered kapag gumamit ka ng naming convention:

// Manual registration (optional)
// app/Providers/AuthServiceProvider.php
class AuthServiceProvider extends ServiceProvider
{
    protected $policies = [
        Post::class => PostPolicy::class,
        Comment::class => CommentPolicy::class,
    ];

    public function boot()
    {
        $this->registerPolicies();
    }
}

// Auto-registration (Laravel 8+)
// Kapag ang policy ay nasa app/Policies/PostPolicy.php
// at ang model ay nasa app/Models/Post.php
// auto-detect na ito ng Laravel.

Using Policies in Controllers

Gamitin ang policies sa controllers para i-protect ang endpoints:

class PostController extends Controller
{
    public function update(UpdatePostRequest $request, Post $post)
    {
        // I-check kung authorized ang user
        $this->authorize('update', $post);

        // OR gamit ang Policy method name
        $this->authorize('update', [$post]);

        // Continue with update...
        $post->update($request->validated());
        return new PostResource($post);
    }

    public function destroy(Post $post)
    {
        $this->authorize('delete', $post);

        $post->delete();
        return response()->noContent();
    }

    // Alternative: Use middleware
    public function __construct()
    {
        $this->middleware('can:update,post')->only('update');
        $this->middleware('can:delete,post')->only('destroy');
    }
}

Checking Authorization:

  • $this->authorize('ability', $model) — I-check ang authorization sa controller. I-throw ng 403 exception kapag unauthorized.
  • auth()->user()->can('ability', $model) — I-check ang authorization sa kahit anong lugar. I-return ng boolean.
  • auth()->user()->cannot('ability', $model) — Reverse ng can().

Practical: User Can Only Edit Own Posts

Gamitin natin ang lahat ng natutunan para i-implement ang ownership-based authorization:

// Step 1: Create Policy
php artisan make:policy PostPolicy --model=Post

// Step 2: Define methods
class PostPolicy
{
    public function update(User $user, Post $post)
    {
        return $user->id === $post->user_id;
    }

    public function delete(User $user, Post $post)
    {
        return $user->id === $post->user_id;
    }
}

// Step 3: Use in Controller
class PostController extends Controller
{
    public function update(UpdatePostRequest $request, Post $post)
    {
        $this->authorize('update', $post);

        $post->update($request->validated());
        return new PostResource($post);
    }

    public function destroy(Post $post)
    {
        $this->authorize('delete', $post);

        $post->delete();
        return response()->noContent();
    }
}

// Step 4: Test
// User A creates a post
// User A can update/delete their own post
// User B CANNOT update/delete User A's post
// Admin can update/delete any post

Role-Based Authorization:

// Adding roles to User model
class User extends Authenticatable
{
    public function isAdmin()
    {
        return $this->role === 'admin';
    }

    public function isModerator()
    {
        return $this->role === 'moderator';
    }
}

// In Policy
public function delete(User $user, Post $post)
{
    // Owner OR admin can delete
    return $user->id === $post->user_id || $user->isAdmin();
}

Quiz

Summary

  • Ang Policies ay dedicated classes para sa authorization logic — organized at testable.
  • Ang Gates ay simple closures para sa authorization — flexible pero hindi organized.
  • Ang $this->authorize() sa controller ay nag-throw ng 403 exception kapag unauthorized.
  • Ang auth()->user()->can() ay nag-return ng boolean — pwedeng gamitin sa kahit anong lugar.
Interview Angle "How do you handle authorization in Laravel?" — Gumagamit ako ng Policies para sa model-specific authorization logic (ownership, roles). I-register ang policies at i-use sa controllers gamit ang $this->authorize() o middleware. Ito ay mas organized at testable kaysa mag-check ng permissions sa bawat controller method.
