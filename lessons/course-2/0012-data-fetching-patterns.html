Data Fetching Patterns

Matutunan kung paano mag-fetch ng data mula sa Laravel API gamit ang Next.js, kasama ang loading states, error handling, at caching behavior.

Lesson Goal Sa lesson na ito, magagawa mong mag-implement ng data fetching sa listing page na may loading skeleton at proper error handling.

Server-Side Data Fetching

Ang pinaka-magandang bagay sa Next.js App Router ay ang server-side data fetching. Sa server components, pwede kang mag-await ng fetch calls nang hindi nag-aalala sa CORS o security issues — ang lahat ay nangyayari sa server bago i-render ang page.

// app/listings/page.js — Server Component
import api from '@/lib/api';
import ListingCard from '@/components/listings/ListingCard';

export default async function ListingsPage() {
  // Direct fetch gamit ang Laravel API
  const listings = await fetch('http://localhost:8000/api/listings', {
    next: { revalidate: 60 } // ISR: revalidate every 60 seconds
  }).then(res => res.json());

  return (
    <div>
      <h1>Listings</h1>
      <div className="grid">
        {listings.map(listing => (
          <ListingCard key={listing.id} listing={listing} />
        ))}
      </div>
    </div>
  );
}

Ang next: { revalidate: 60 } ay tumutukoy sa Incremental Static Regeneration (ISR). Ibig sabihin, ang page ay naka-cache ng 60 seconds — pagkatapos non, ang susunod na visit ay magre-revalidate. Ito ay best of both worlds: mabilis gaya ng static pero updated pa rin.

Loading States gamit ang Suspense

Ang Next.js ay may built-in na paraan para magpakita ng loading state habang naglo-load ang data — gamit ang loading.js file. Ito ay gagamit ng React Suspense under the hood.

Lumikha ng loading.js sa same folder ng page.js:

// app/listings/loading.js
export default function ListingsLoading() {
  return (
    <div className="skeleton-container">
      <div className="skeleton-header">
        <div className="skeleton skeleton-title" />
      </div>
      <div className="grid">
        {Array.from({ length: 6 }).map((_, i) => (
          <div key={i} className="skeleton-card">
            <div className="skeleton skeleton-image" />
            <div className="skeleton skeleton-text" />
            <div className="skeleton skeleton-text short" />
          </div>
        ))}
      </div>
    </div>
  );
}

Pag nag-navigate ang user sa /listings, makikita niya agad ang skeleton habang naglo-load ang data. Hindi na kailangan ng manual useState para sa loading state — ginagawa na ito ng Next.js automatically.

Error Handling

Para sa error handling, gumamit ng error.js file. Ito ay mag-a-automatically wrap ang page sa error boundary:

// app/listings/error.js
'use client';

export default function ListingsError({ error, reset }) {
  return (
    <div className="error-container">
      <h2>Nagkaroon ng problema!</h2>
      <p>Hindi ma-load ang listings. Please try again.</p>
      <p className="error-message">{error.message}</p>
      <button onClick={() => reset()}>Try Again</button>
    </div>
  );
}

Pansinin na ang error.js ay kailangang maging client component — ito ang nagbibigay ng reset function para ma-retry ang rendering.

Caching Behavior ng fetch

Ang Next.js fetch ay may iba't ibang caching options:

  • Default (no options) — Ang data ay naka-cache sa request time at hindi magre-revalidate unless manual. Ang data ay static hanggang sa i-deploy mo ulit.
  • next: { revalidate: N } — ISR mode. Ang data ay magre-revalidate pagkatapos ng N seconds.
  • next: { tags: ['listings'] } — Tag-based revalidation. Pwede mong i-revalidate ang specific data gamit ang revalidateTag('listings').
  • cache: 'no-store' — Walang caching. Laging fresh data. Gamitin lang kapag talagang kailangan ng real-time data.
// Walang caching — laging fresh
const res = await fetch('http://localhost:8000/api/listings', {
  cache: 'no-store'
});

// Tag-based revalidation
const res = await fetch('http://localhost:8000/api/listings', {
  next: { tags: ['listings'] }
});

// Pagkatapos ng mutation, i-revalidate:
import { revalidateTag } from 'next/cache';
revalidateTag('listings');

Para sa Laravel integration, ang pinaka-practical na approach ay gumamit ng cache: 'no-store' muna habang nagde-develop — para makita mo agad ang latest data. Pag production na, pwede kang mag-switch sa ISR o tag-based caching.

Practical: Listing Page with Loading at Error States

I-combine natin ang lahat ng natutunan sa isang complete listing page:

// app/listings/page.js
import api from '@/lib/api';
import ListingCard from '@/components/listings/ListingCard';

export default async function ListingsPage() {
  let listings;

  try {
    const res = await fetch('http://localhost:8000/api/listings', {
      cache: 'no-store',
    });

    if (!res.ok) {
      throw new Error(`Failed to fetch listings: ${res.status}`);
    }

    listings = await res.json();
  } catch (error) {
    return (
      <div className="error-container">
        <h2>Hindi ma-load ang listings</h2>
        <p>{error.message}</p>
      </div>
    );
  }

  return (
    <div>
      <h1>All Listings</h1>
      {listings.length === 0 ? (
        <p>Walang listings pa.</p>
      ) : (
        <div className="grid">
          {listings.map(listing => (
            <ListingCard key={listing.id} listing={listing} />
          ))}
        </div>
      )}
    </div>
  );
}

Ito ang malinis na pattern: fetch sa server, handle ang error, at i-render ang data. Hindi mo kailangan ng useEffect o useState para sa data fetching — ginagawa na ito ng server component.

Quiz

Summary

  • Server components ang pinaka-natural na paraan ng data fetching sa Next.js — walang CORS issues, walang extra JavaScript sa client.
  • Gamitin ang loading.js para sa automatic loading states at error.js para sa error boundaries.
  • Ang fetch sa Next.js ay may built-in caching — gamitin ang cache: 'no-store' para sa fresh data o ISR para sa performance.
  • I-push ang error handling sa server component — mas malinis at hindi nag-aalala sa client-side state.
