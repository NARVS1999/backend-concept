Basic CI/CD

Paano i-automate ang testing at deployment para hindi ka na mag-manually mag-deploy? Introduction sa GitHub Actions para sa Laravel at Next.js.

Lesson Goal Sa lesson na ito, magagawa mong gumawa ng GitHub Actions workflow na nag-automate ng tests at deployment para sa Laravel at Next.js, maintindihan ang CI/CD pipeline, at malaman ang mga deployment strategies na pwedeng gamitin.

Ano ang CI/CD?

CI (Continuous Integration) ay ang practice ng pag-push ng code changes sa shared repository nang frequently. Bawat push ay naka-automate na nagru-run ng tests para ma-verify na hindi na-break ang existing functionality.

CD (Continuous Deployment/Delivery) ay ang practice ng pag-deploy ng verified code changes sa production environment nang automated. Kapag pasado ang tests, i-deploy agad — walang manual intervention.

CI/CD Pipeline flow:

Developer pushes code
        ↓
GitHub Actions detects push
        ↓
┌─────────────────────────┐
│  Step 1: Install deps   │
│  (composer/npm install) │
├─────────────────────────┤
│  Step 2: Run linter     │
│  (phpcs / eslint)       │
├─────────────────────────┤
│  Step 3: Run tests      │
│  (phpunit / jest)       │
├─────────────────────────┤
│  Step 4: Build          │
│  (npm run build)        │
└─────────────────────────┘
        ↓
  All passed? → Deploy
  Failed? → Notify, block merge

Ang CI/CD ay nagbibigay ng confidence — alam mong hindi ka magbe-break ng production kapag may bumagsak na test. Ito rin ay nagpapabilis ng development cycle dahil hindi ka na nag-wa-wait ng manual testing bago mag-deploy.

GitHub Actions Setup para sa Laravel

Ang GitHub Actions ay ang CI/CD platform ng GitHub — naka-integrate na at may free tier para sa public repositories (unlimited) at private repositories (2000 minutes/month).

Gumawa ng .github/workflows/laravel.yml file sa root ng Laravel project:

# .github/workflows/laravel.yml
name: Laravel CI

on:
  push:
    branches: [main, develop]
  pull_request:
    branches: [main]

jobs:
  test:
    runs-on: ubuntu-latest

    services:
      mysql:
        image: mysql:8.0
        env:
          MYSQL_ROOT_PASSWORD: password
          MYSQL_DATABASE: roxy_test
          MYSQL_USER: testing
          MYSQL_PASSWORD: password
        ports:
          - 3306:3306
        options: >-
          --health-cmd="mysqladmin ping"
          --health-interval=10s
          --health-timeout=5s
          --health-retries=5

    steps:
      - uses: actions/checkout@v4

      - name: Setup PHP
        uses: shivammathur/setup-php@v2
        with:
          php-version: '8.2'
          extensions: mbstring, xml, ctype, json, bcmath, gd, mysql
          coverage: none

      - name: Cache Composer dependencies
        uses: actions/cache@v3
        with:
          path: vendor
          key: ${{ runner.os }}-composer-${{ hashFiles('**/composer.lock') }}

      - name: Install Dependencies
        run: composer install --no-progress --prefer-dist

      - name: Prepare Environment
        run: |
          cp .env.example .env
          php artisan key:generate

      - name: Run Migrations
        env:
          DB_CONNECTION: mysql
          DB_HOST: 127.0.0.1
          DB_PORT: 3306
          DB_DATABASE: roxy_test
          DB_USERNAME: testing
          DB_PASSWORD: password
        run: php artisan migrate --force

      - name: Run Tests
        env:
          DB_CONNECTION: mysql
          DB_HOST: 127.0.0.1
          DB_PORT: 3306
          DB_DATABASE: roxy_test
          DB_USERNAME: testing
          DB_PASSWORD: password
        run: php artisan test

      - name: Run Linter
        run: vendor/bin/phpcs --standard=PSR12 app/

Ang workflow na ito ay nag-automate ng: install dependencies, setup MySQL service, run migrations, run tests, at i-check ang code style. Kapag may failed test o linter error, hindi ma-merge ang pull request.

GitHub Actions Setup para sa Next.js

Gumawa ng .github/workflows/nextjs.yml file:

# .github/workflows/nextjs.yml
name: Next.js CI

on:
  push:
    branches: [main, develop]
  pull_request:
    branches: [main]

jobs:
  test:
    runs-on: ubuntu-latest

    steps:
      - uses: actions/checkout@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'

      - name: Install Dependencies
        run: npm ci

      - name: Run Linter
        run: npm run lint

      - name: Run Tests
        run: npm test

      - name: Build
        run: npm run build
        env:
          NEXT_PUBLIC_API_URL: http://localhost:8000/api

Ang Next.js workflow ay mas simple — install, lint, test, build. Ang build step ay importante dahil dito nito nadi-detect ang compilation errors at missing environment variables.

Deployment Strategies

Pagkatapos ng CI (tests passed), pwede mong i-deploy ang code. Narito ang mga common na deployment strategies:

1. Git-based deployment (simplest):

# Sa VPS server - deploy script
#!/bin/bash
cd /var/www/roxy
git pull origin main
composer install --no-dev --optimize-autoloader
php artisan migrate --force
php artisan config:cache
php artisan route:cache
php artisan view:cache
sudo systemctl restart php8.2-fpm
sudo systemctl restart nginx

Ito ay ang pinakamadaling approach — i-pull lang ang latest code, i-install ang dependencies, i-run ang migrations, at i-restart ang services. Pwede mong i-automate ang deploy script gamit ang GitHub Actions.

2. Zero-downtime deployment:

# Sa VPS - zero-downtime deployment
# I-setup ang bagong release directory
RELEASE_DIR="/var/www/roxy/releases/$(date +%Y%m%d%H%M%S)"
SHARED_DIR="/var/www/roxy/shared"
CURRENT_DIR="/var/www/roxy/current"

# I-clone ang bagong release
git clone -b main https://github.com/you/roxy.git $RELEASE_DIR

# I-symlink ang shared resources (storage, .env)
ln -s $SHARED_DIR/storage $RELEASE_DIR/storage
ln -s $SHARED_DIR/.env $RELEASE_DIR/.env

# I-install at i-build
cd $RELEASE_DIR
composer install --no-dev
npm ci && npm run build
php artisan migrate --force

# I-update ang symlink (atomic switch)
ln -sfn $RELEASE_DIR $CURRENT_DIR

# I-reload ang services
sudo systemctl reload php8.2-fpm

Ang zero-downtime deployment ay gumagamit ng symlink switching — ang bagong release ay naka-setup na bago i-switch ang live traffic. Walang downtime sa pagitan ng old at new version.

3. Container-based deployment (Docker):

# Dockerfile para sa Laravel
FROM php:8.2-fpm

RUN apt-get update && apt-get install -y \
    git curl zip unzip libpng-dev libonig-dev \
    libxml2-dev libzip-dev

RUN docker-php-ext-install pdo_mysql mbstring exif pcntl bcmath gd zip

COPY --from=composer:latest /usr/bin/composer /usr/bin/composer

WORKDIR /var/www/html
COPY . .
RUN composer install --no-dev --optimize-autoloader
RUN php artisan config:cache && php artisan route:cache

EXPOSE 9000
CMD ["php-fpm"]

Ang Docker deployment ay nagbibigay ng consistency — ang app ay gumagana ng pareho sa development at production. Ito ay mas complex setup pero mas reliable para sa team environments.

Practical: Create Your CI/CD Pipeline

Step 1: Gumawa ng .github/workflows/ directory sa root ng Laravel project. I-create ang laravel.yml workflow file gamit ang template sa itaas.

Step 2: I-commit at i-push ang workflow file sa GitHub. I-check ang "Actions" tab para makita ang workflow run — dapat mag-pass ang tests.

Step 3: Gumawa ng .github/workflows/nextjs.yml para sa Next.js project. I-setup ang Node.js, install, lint, test, at build steps.

Step 4: I-test ang pipeline: gumawa ng bagong branch, mag-add ng test na intentionally mag-fail, gumawa ng pull request. Dapat mag-fail ang CI at hindi ma-merge.

Step 5: I-fix ang failing test, i-push ang fix. Dapat mag-pass na ang CI at pwede nang i-merge ang pull request.

Step 6: I-setup ang auto-deployment: kapag na-merge sa main branch, i-deploy agad sa production server gamit ang deploy script. I-test ang buong flow — push to deploy.

Quiz

Summary

  • Ang CI (Continuous Integration) ay nag-automate ng tests sa bawat code push — nagpapahintulot ng safe na collaboration
  • Ang CD (Continuous Deployment) ay nag-a-auto-deploy ng verified code sa production — walang manual intervention
  • Ang GitHub Actions ay free at easy to set up para sa Laravel at Next.js projects
  • Ang git-based deployment ay ang simplest approach — pull, install, migrate, restart
  • Ang zero-downtime deployment ay gumagamit ng symlink switching para walang interruption sa production
