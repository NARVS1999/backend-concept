Database Schema Planning

Matutunan kung paano mag-design ng database schema gamit ang ERD, core tables, at relationships — lahat Laravel-specific para sa ating Roxy project.

Lesson Goal Sa lesson na ito, magagawa mong mag-design ng Entity Relationship Diagram (ERD) at database schema para sa iyong Laravel + MySQL project, gamit ang mermaid diagrams at proper table relationships.

Bakit Kailangan ng Schema Planning?

Ang database schema ang blueprint ng iyong data — ano ang ini-store, paano nag-re-relate ang tables, at ano ang constraints. Kapag mali ang schema, mahirap na ito i-change later (migration nightmares!).

Ito ang mga common na problema kapag hindi nag-plano:

  • Duplicate data — Nag-store ng user info sa multiple tables, hindi normalized.
  • Missing relationships — Hindi alam kung paano i-connect ang orders sa users.
  • Performance issues — Walang indexes sa frequently queried columns.
  • Data integrity problems — Pwede mag-exist ang orphan records na walang parent.

Ang solusyon: mag-design muna bago mag-migrate.

Entity Relationship Diagrams (ERD)

Ang ERD ay visual representation ng iyong database — ang tables (entities), ang columns, at ang relationships. Gamitin natin ang mermaid syntax para sa ating ERD.

Para sa ating Roxy project (e-commerce), heto ang ERD:

Core Tables at Relationships

Break down natin ang bawat table at ang relationships:

Users Table — Ang central table. Lahat ng users dito.

// Laravel Migration
Schema::create('users', function (Blueprint $table) {
    $table->id();
    $table->string('name');
    $table->string('email')->unique();
    $table->string('password');
    $table->timestamp('email_verified_at')->nullable();
    $table->timestamps();
});

Products Table — May foreign key sa categories.

Schema::create('products', function (Blueprint $table) {
    $table->id();
    $table->foreignId('category_id')->constrained()->cascadeOnDelete();
    $table->string('name');
    $table->text('description')->nullable();
    $table->decimal('price', 10, 2);
    $table->integer('stock')->default(0);
    $table->string('image_url')->nullable();
    $table->boolean('is_active')->default(true);
    $table->timestamps();
});

Orders + Order Items — Ang order ay parent, order_items ang children (one-to-many).

Schema::create('orders', function (Blueprint $table) {
    $table->id();
    $table->foreignId('user_id')->constrained()->cascadeOnDelete();
    $table->string('order_number')->unique();
    $table->decimal('total_amount', 10, 2);
    $table->string('status')->default('pending');
    $table->timestamps();
});

Schema::create('order_items', function (Blueprint $table) {
    $table->id();
    $table->foreignId('order_id')->constrained()->cascadeOnDelete();
    $table->foreignId('product_id')->constrained()->cascadeOnDelete();
    $table->integer('quantity');
    $table->decimal('unit_price', 10, 2);
    $table->decimal('subtotal', 10, 2);
});

Relationship Types:

  • One-to-Many — User has many Orders (user_id sa orders table)
  • Many-to-One — Product belongs to Category (category_id sa products table)
  • Many-to-Many — Products and Orders connected through Order Items (pivot table)
  • One-to-One — Order has one Payment (order_id sa payments table)

Laravel Relationships sa Code

Ito ang Eloquent relationships na gagamitin mo sa Laravel models:

// User Model
class User extends Authenticatable
{
    public function orders()
    {
        return $this->hasMany(Order::class);
    }

    public function addresses()
    {
        return $this->hasMany(Address::class);
    }

    public function reviews()
    {
        return $this->hasMany(Review::class);
    }
}

// Product Model
class Product extends Model
{
    public function category()
    {
        return $this->belongsTo(Category::class);
    }

    public function orderItems()
    {
        return $this->hasMany(OrderItem::class);
    }

    public function reviews()
    {
        return $this->hasMany(Review::class);
    }
}

// Order Model
class Order extends Model
{
    public function user()
    {
        return $this->belongsTo(User::class);
    }

    public function items()
    {
        return $this->hasMany(OrderItem::class);
    }

    public function payment()
    {
        return $this->hasOne(Payment::class);
    }
}

Practical Exercise: Design Your ERD

Subukan mo ito para sa iyong own project:

## Exercise: ERD Design

1. I-list ang lahat ng "entities" sa iyong project
   (Users, Products, Orders, etc.)

2. For each entity, list ang columns:
   - ID (always bigint auto-increment)
   - Foreign keys (always foreignId->constrained)
   - Business data (strings, decimals, text)
   - Timestamps (created_at, updated_at)

3. I-define ang relationships:
   - One-to-Many: User has many Orders
   - Many-to-One: Product belongs to Category
   - Many-to-Many: Users and Roles (pivot table)

4. Gumawa ng ERD gamit ang mermaid syntax
   - Pakita sa AI agent for review
   - Ask: "Are there missing relationships?"
   - Ask: "Am I missing any indexes?"

5. I-generate ang migrations
   - php artisan make:model Category -m
   - php artisan make:model Product -m
   - etc.

Summary

  • Ang database schema ang blueprint ng data — dapat i-design bago mag-migrate para maiwasan ang problems later.
  • Ang ERD (Entity Relationship Diagram) ang visual representation ng tables at relationships — gamitin ang mermaid syntax.
  • Ang foreign key constraints (foreignId->constrained) ang nag-eensure ng data integrity sa pagitan ng tables.
  • Laravel Eloquent relationships (hasMany, belongsTo, hasOne) ang nag-co-connect ng models sa application layer.
