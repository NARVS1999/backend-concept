Migrations & Eloquent Models

Matutunan kung paano i-structure ang database schema gamit ang Laravel migrations at i-map ito sa Eloquent models para sa malinis at maintainable na backend.

Lesson Goal Sa lesson na ito, magagawa mong gumawa ng database migrations mula sa Phase 0 schema, i-create ang mga Eloquent models na may tamang relationships, at ma-configure ang fillable/guarded properties.

Ano ang Laravel Migrations?

Ang migrations ay parang version control para sa iyong database. Sa halip na manually mag-run ng SQL statements, gumagawa ka ng PHP classes na nag-declare ng schema changes. Ito ay:

  • Reproducible — Pwede mong i-run ang migrations sa kahit anong environment (local, staging, production) at magkakaroon ka ng parehong schema.
  • Collaborative — Kapag nag-commit ka ng migration files, pwedeng i-pull ng ibang developers at i-run ang migrations nila.
  • reversible — Pwede mong i-rollback ang migrations gamit ang php artisan migrate:rollback.

Ang file naming convention ay YYYY_MM_DD_HHMMSS_create_users_table.php. Ito ay auto-generated kapag gumamit ka ng php artisan make:migration.

// Example migration for posts table
Schema::create('posts', function (Blueprint $table) {
    $table->id();
    $table->foreignId('user_id')->constrained()->cascadeOnDelete();
    $table->string('title');
    $table->text('body')->nullable();
    $table->enum('status', ['draft', 'published', 'archived'])->default('draft');
    $table->timestamps();
    $table->softDeletes();
});

Best Practices:

  • Laging gamitin ang foreignId()->constrained() para sa foreign keys — ito ay auto-ma-detect ang table at column name.
  • I-set ang cascadeOnDelete() o restrictOnDelete() depende sa business logic.
  • Magdagdag ng softDeletes() kung ayaw mong talagang i-delete ang records.
  • Pwede kang mag-add ng indexes gamit ang $table->index('column') para sa performance.

Eloquent Models & Relationships

Ang Eloquent ay Laravel's ORM (Object-Relational Mapping). Bawat table sa database ay may corresponding na Model class. Ang models ang nag-handle ng business logic at relationships.

Common Relationships:

// User Model - has many posts
class User extends Authenticatable
{
    public function posts()
    {
        return $this->hasMany(Post::class);
    }
    
    public function roles()
    {
        return $this->belongsToMany(Role::class);
    }
}

// Post Model - belongs to user, has many comments
class Post extends Model
{
    protected $fillable = ['title', 'body', 'status', 'user_id'];
    
    public function user()
    {
        return $this->belongsTo(User::class);
    }
    
    public function comments()
    {
        return $this->hasMany(Comment::class);
    }
    
    public function tags()
    {
        return $this->belongsToMany(Tag::class);
    }
}

// Comment Model - belongs to post and user
class Comment extends Model
{
    protected $fillable = ['body', 'user_id', 'post_id'];
    
    public function post()
    {
        return $this->belongsTo(Post::class);
    }
    
    public function user()
    {
        return $this->belongsTo(User::class);
    }
}

Fillable vs Guarded:

  • $fillable — Array ng columns na pwedeng i-mass assign. Ito ang "allow list."
  • $guarded — Array ng columns na HINDI pwedeng i-mass assign. Ito ang "block list."
  • Piliin mo ang isa — wag mong gagamitin pareho sa iisang model.
  • Para sa security, mas mainam gamitin ang $guarded = [] (walang guarded) kapag alam mo ang ginagawa.

Timestamps & Soft Deletes

Ang Laravel ay auto-manage ng created_at at updated_at columns kapag gumamit ka ng timestamps() sa migration. Para i-disable:

class Post extends Model
{
    const CREATED_AT = null;
    const UPDATED_AT = null;
    
    // OR sa migration:
    $table->timestamps(false); // walang timestamps
}

Practical: Implement Schema from Phase 0

Gamitin natin ang database schema na ginawa mo sa Phase 0. Halimbawa, kung meron kang Users, Posts, at Comments tables:

// Step 1: Create migrations
php artisan make:migration create_users_table
php artisan make:migration create_posts_table
php artisan make:migration create_comments_table

// Step 2: Create models
php artisan make:model User
php artisan make:model Post
php artisan make:model Comment

// Step 3: Run migrations
php artisan migrate

// Step 4: Test in Tinker
php artisan tinker
>>> $user = User::factory()->create();
>>> $post = $user->posts()->create(['title' => 'Hello', 'body' => 'World']);
>>> $post->user; // Returns the user
>>> $user->posts; // Returns collection of posts

Tips para sa Real Projects:

  • Mag-create ng migration para sa lahat ng tables bago ka mag-create ng models.
  • Palaging i-check ang foreign key constraints — wag mong kalimutan ang constrained().
  • Mag-add ng indexes sa columns na madalas ginagamit sa queries (like user_id, status).
  • Gamitin ang php artisan migrate:fresh --seed para mag-reset ng database during development.

Summary

  • Ang migrations ay version control para sa database schema — reproducible, collaborative, at reversible.
  • Ang Eloquent models ang nag-map ng database tables sa PHP classes, at nag-handle ng relationships (hasMany, belongsTo, belongsToMany).
  • Ang $fillable ay allow list para sa mass assignment, habang ang $guarded ay block list.
  • Ang timestamps at soft deletes ay auto-managed ng Laravel para sa audit trail at data recovery.
Interview Angle "Explain the difference between $fillable and $guarded in Laravel." — Ang sagot: Ang $fillable ay allow list para sa mass assignment (safe columns lang), habang ang $blocked ay block list (lahat pwede maliban sa mga naka-list). Piliin mo ang isa para i-avoid ang mass assignment vulnerabilities.
