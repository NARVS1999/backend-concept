API Resources & Controllers

Matutunan kung paano mag-structure ng RESTful controllers, gumamit ng API Resources para sa response shaping, at mag-implement ng Form Requests para sa validation.

Lesson Goal Sa lesson na ito, magagawa mong gumawa ng full CRUD endpoint para sa isang core entity gamit ang tamang Resource classes, Form Request validation, at RESTful controller structure.

RESTful Controller Structure

Ang RESTful controllers ay nag-oorganisa ng endpoints ayon sa HTTP verbs at resource paths. Sa Laravel, ito ang standard pattern:

class PostController extends Controller
{
    // GET /posts
    public function index()
    {
        $posts = Post::with('user')->latest()->paginate(15);
        return PostResource::collection($posts);
    }

    // GET /posts/{id}
    public function show(Post $post)
    {
        return new PostResource($post->load(['user', 'comments.user']));
    }

    // POST /posts
    public function store(StorePostRequest $request)
    {
        $post = auth()->user()->posts()->create($request->validated());
        return new PostResource($post);
    }

    // PUT/PATCH /posts/{id}
    public function update(UpdatePostRequest $request, Post $post)
    {
        $post->update($request->validated());
        return new PostResource($post);
    }

    // DELETE /posts/{id}
    public function destroy(Post $post)
    {
        $post->delete();
        return response()->noContent();
    }
}

Key Points:

  • Ang index() ay nag-return ng collection — gamitin ang ::collection() ng Resource.
  • Ang show() ay nag-return ng single resource — gamitin ang new Resource().
  • Ang store() at update() ay gumagamit ng Form Requests para sa validation.
  • Ang destroy() ay nag-return ng 204 No Content kapag successful.
  • Palaging i-attach ang related models gamit ang with() para i-avoid ang N+1 query problem.

API Resources for Response Shaping

Ang API Resources ang nag-sshape ng JSON response na ibabalik sa frontend. Ito ang "presentation layer" ng backend.

// PostResource.php
class PostResource extends JsonResource
{
    public function toArray($request)
    {
        return [
            'id' => $this->id,
            'title' => $this->title,
            'body' => $this->body,
            'status' => $this->status,
            'slug' => $this->slug,
            'created_at' => $this->created_at->toISOString(),
            'updated_at' => $this->updated_at->toISOString(),
            'user' => new UserResource($this->whenLoaded('user')),
            'comments_count' => $this->whenCounted('comments'),
            'comments' => CommentResource::collection($this->whenLoaded('comments')),
        ];
    }
}

// UserResource.php
class UserResource extends JsonResource
{
    public function toArray($request)
    {
        return [
            'id' => $this->id,
            'name' => $this->name,
            'email' => $this->email,
            'avatar' => $this->avatar,
            'created_at' => $this->created_at->toISOString(),
        ];
    }
}

Mga Importanteng Methods:

  • $this->whenLoaded('relation') — I-return lang ang data kapag naka-load ang relationship. Ito ang "conditional loading."
  • $this->whenCounted('relation') — I-return lang ang count kapag na-count na ang relationship.
  • $this->merge($array) — I-merge ang additional fields sa array.
  • $this->additional(['key' => 'value']) — Magdagdag ng additional top-level fields.

Collection Resources:

// Kapag nag-return ka ng collection, pwede kang mag-customize
PostResource::collection($posts)->additional([
    'meta' => [
        'current_page' => $posts->currentPage(),
        'last_page' => $posts->lastPage(),
        'per_page' => $posts->perPage(),
        'total' => $posts->total(),
    ]
]);

Form Requests for Validation

Ang Form Requests ay dedicated classes na nag-handle ng validation logic. Ito ay mas malinis kaysa mag-validate sa loob ng controller.

// StorePostRequest.php
class StorePostRequest extends FormRequest
{
    public function authorize()
    {
        return true; // or check permissions
    }

    public function rules()
    {
        return [
            'title' => 'required|string|max:255',
            'body' => 'nullable|string',
            'status' => 'required|in:draft,published,archived',
            'tags' => 'nullable|array',
            'tags.*' => 'exists:tags,id',
        ];
    }

    public function messages()
    {
        return [
            'title.required' => 'Ang title ay required.',
            'title.max' => 'Ang title ay hindi dapat lumagpas sa 255 characters.',
            'status.in' => 'Ang status ay dapat draft, published, o archived.',
        ];
    }
}

Mga Advanced Validation Rules:

  • unique:table,column — Para sa uniqueness checks (e.g., unique email).
  • exists:table,column — Para sa foreign key validation.
  • after:date — Para sa date validation (e.g., start_date before end_date).
  • nullable — Para sa optional fields.
  • required_with:field — Required kapag may value ang specified field.

Practical: Full CRUD Endpoint

Gamitin natin ang lahat ng natutunan para gumawa ng full CRUD para sa Posts:

// Step 1: Create Form Requests
php artisan make:request StorePostRequest
php artisan make:request UpdatePostRequest

// Step 2: Create API Resource
php artisan make:resource PostResource

// Step 3: Create Controller
php artisan make:controller PostController --api --model=Post

// Step 4: Define Routes
Route::apiResource('posts', PostController::class);

// Step 5: Test in Postman/Insomnia
GET /api/posts → Collection with pagination
GET /api/posts/1 → Single post with user and comments
POST /api/posts → Create with validation
PUT /api/posts/1 → Update with validation
DELETE /api/posts/1 → Delete (204 No Content)

Tips para sa Real Projects:

  • Palaging gumamit ng API Resources — wag mong i-return ang raw model data.
  • I-separate ang validation sa Form Requests — wag mong i-mix sa controller.
  • Gamitin ang apiResource() sa routes para sa auto-generated RESTful routes.
  • Mag-add ng pagination sa index endpoints — wag mong i-return ang lahat ng records.
  • I-serialize ang dates gamit ang ->toISOString() para sa consistent format.

Summary

  • Ang API Resources ang nag-sshape ng JSON response — ang "presentation layer" ng backend.
  • Ang Form Requests ay dedicated classes para sa validation logic — mas malinis kaysa mag-validate sa controller.
  • Laging i-attach ang related models gamit ang with() para i-avoid ang N+1 query problem.
