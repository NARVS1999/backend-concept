Monitoring & Error Tracking

Paano mo malalaman kapag may problema sa production app mo? Introduction sa logging, error tracking, at uptime monitoring.

Lesson Goal Sa lesson na ito, magagawa mong i-setup ang error tracking para sa Laravel at Next.js gamit ang Sentry, i-configure ang logging, i-setup ang uptime monitoring, at malaman kung paano mag-respond sa production issues.

Bakit Kailangan ng Monitoring?

Kapag na-deploy na ang app mo sa production, hindi mo na makikita ang mga errors sa terminal — ang users lang ang makakaranas ng problema. Walang monitoring = walang visibility sa kung ano ang nangyayari sa production.

Problems na nangyayari sa production:

  • Database connection timeout — bumagal ang server at nag-timeout ang mga requests
  • Memory exhaustion — na-oom ang server dahil sa maraming concurrent users
  • Third-party API failure — bumagsak ang Stripe/Payment API at hindi na-process ang orders
  • File upload errors — hindi ma-upload ang images dahil sa disk space issue
  • Authentication bugs — hindi makaka-login ang users dahil sa expired tokens

Kung walang monitoring, malalaman mo lang ang problema kapag nag-complain na ang users — or worse, hindi mo malalaman at tuloy-tuloy ang damage. Ang monitoring ay nagbibigay ng early warning system para ma-address ang issues bago pa lumala.

Laravel Logging Setup

Ang Laravel ay may built-in na logging system gamit ang Monolog. I-configure ang logging sa config/logging.php:

// config/logging.php
return [
    'default' => env('LOG_CHANNEL', 'stack'),

    'channels' => [
        'stack' => [
            'driver' => 'stack',
            'channels' => ['daily', 'errorlog'],
            'ignore_exceptions' => false,
        ],

        'daily' => [
            'driver' => 'daily',
            'path' => storage_path('logs/laravel.log'),
            'level' => env('LOG_LEVEL', 'info'),
            'days' => 14,  // auto-delete after 14 days
        ],

        'errorlog' => [
            'driver' => 'errorlog',
            'level' => env('LOG_LEVEL', 'debug'),
        ],

        'stderr' => [
            'driver' => 'monolog',
            'level' => env('LOG_LEVEL', 'debug'),
            'handler' => Monolog\Handler\StreamHandler::class,
            'formatter' => env('LOG_STDERR_FORMATTER'),
            'with' => [
                'stream' => 'php://stderr',
            ],
        ],
    ],
];

Basic logging sa Laravel code:

use Illuminate\Support\Facades\Log;

// Info level - general information
Log::info('User logged in', ['user_id' => $user->id]);

// Warning level - potential issues
Log::warning('Payment API response slow', [
    'response_time' => $responseTime,
    'user_id' => $user->id,
]);

// Error level - actual errors
Log::error('Failed to process payment', [
    'user_id' => $user->id,
    'amount' => $order->total,
    'error' => $e->getMessage(),
]);

// Critical level - system-level failures
Log::critical('Database connection lost', [
    'host' => config('database.connections.mysql.host'),
]);

Contextual logging sa controllers:

class OrderController extends Controller
{
    public function store(Request $request)
    {
        try {
            $order = Order::create($validated);

            Log::info('Order created', [
                'order_id' => $order->id,
                'user_id' => auth()->id(),
                'total' => $order->total,
            ]);

            return response()->json(['data' => $order], 201);

        } catch (\Exception $e) {
            Log::error('Order creation failed', [
                'user_id' => auth()->id(),
                'error' => $e->getMessage(),
                'trace' => $e->getTraceAsString(),
            ]);

            return response()->json([
                'message' => 'Failed to create order'
            ], 500);
        }
    }
}

Error Tracking gamit ang Sentry

Ang Sentry ay isang error tracking platform na nagko-collect, nag-a-analyze, at nag-no-notify ng errors sa real-time. Ito ay mas powerful kaysa sa basic logging — may stack traces, breadcrumbs, user context, at performance monitoring.

Setup para sa Laravel:

# I-install ang Sentry Laravel SDK
composer require sentry/sentry-laravel

# I-setup ang Sentry
php artisan sentry:install

# Sa .env, i-add ang Sentry DSN
SENTRY_LARAVEL_DSN=https://xxxxx@sentry.io/xxxxx
SENTRY_TRACES_SAMPLE_RATE=1.0

Sa App/Exceptions/Handler.php, i-configure ang Sentry:

// app/Exceptions/Handler.php
use Sentry\Laravel\SentryServiceProvider;

class Handler extends ExceptionHandler
{
    public function register(): void
    {
        $this->reportable(function (Throwable $e) {
            // Sentry ay awtomatik na nag-capture ng exceptions
            // I-add ang user context para sa better debugging
            if (auth()->check()) {
                \Sentry\configureScope(function (\Sentry\State\HubInterface $scope) {
                    $scope->setUser([
                        'id' => auth()->id(),
                        'email' => auth()->user()->email,
                    ]);
                });
            }
        });
    }
}

Setup para sa Next.js:

# I-install ang Sentry SDK
npm install @sentry/nextjs

# I-setup ang Sentry (gamit ang wizard)
npx @sentry/wizard@latest -i nextjs

# Sa sentry.client.config.ts
import * as Sentry from "@sentry/nextjs";

Sentry.init({
  dsn: process.env.NEXT_PUBLIC_SENTRY_DSN,
  tracesSampleRate: 1.0,
  environment: process.env.NODE_ENV,
});

Manual error capture sa Next.js:

// app/api/checkout/route.ts
import * as Sentry from "@sentry/nextjs";

export async function POST(request: Request) {
  try {
    const data = await request.json();
    // process checkout...
    return Response.json({ success: true });
  } catch (error) {
    Sentry.captureException(error, {
      tags: { module: 'checkout' },
      extra: { requestBody: data },
    });
    return Response.json(
      { error: 'Checkout failed' },
      { status: 500 }
    );
  }
}

Ang Sentry ay nagbibigay ng detailed error information: stack trace, user info, breadcrumbs (kung ano ang nauna bago mag-error), at performance metrics. Ito ay essential para sa pag-diagnose ng production issues.

Uptime Monitoring at Health Checks

Ang uptime monitoring ay nagche-check kung accessible pa ang app mo. Kapag hindi na-reach ang server, mag-no-notify agad — bago pa makapag-complain ang users.

Health check endpoint sa Laravel:

// routes/api.php
Route::get('/health', function () {
    $checks = [
        'app' => 'ok',
        'database' => 'unknown',
        'cache' => 'unknown',
        'disk' => 'unknown',
    ];

    // Check database connection
    try {
        DB::connection()->getPdo();
        $checks['database'] = 'ok';
    } catch (\Exception $e) {
        $checks['database'] = 'error: ' . $e->getMessage();
    }

    // Check cache connection
    try {
        Cache::store('redis')->ping();
        $checks['cache'] = 'ok';
    } catch (\Exception $e) {
        $checks['cache'] = 'error: ' . $e->getMessage();
    }

    // Check disk space
    $freeSpace = disk_free_space('/');
    $checks['disk'] = $freeSpace > 1073741824 ? 'ok' : 'low';

    $allOk = !in_array('error', array_map(function($v) {
        return explode(': ', $v)[0];
    }, $checks));

    return response()->json([
        'status' => $allOk ? 'healthy' : 'degraded',
        'checks' => $checks,
    ], $allOk ? 200 : 503);
});

Uptime monitoring services:

  • UptimeRobot — Free tier na 50 monitors, 5-minute intervals. Simple at reliable.
  • Better Stack — Modern uptime monitoring na may status pages at incident management.
  • Checkly — API at browser monitoring na may playwright integration.

I-configure ang health check URL sa monitoring service: https://api.roxy.com/api/health. I-set ang 5-minute interval at i-configure ang notifications (email, Slack, SMS) kapag bumagsak ang health check.

Practical: Set Up Full Monitoring Stack

Step 1: Gumawa ng Sentry account (free tier: 5000 errors/month). I-setup ang Laravel at Next.js SDKs — i-install, i-configure ang DSN, at i-test ang error reporting.

Step 2: I-configure ang Laravel logging: i-set ang daily log rotation (14 days), i-add ang context sa important operations (login, orders, payments), at i-setup ang log shipping sa external service (optional).

Step 3: Gumawa ng /api/health endpoint sa Laravel na nagche-check ng database, cache, at disk space. I-test na nagre-return ng 200 OK kapag healthy at 503 kapag may issue.

Step 4: I-setup ang UptimeRobot: i-create ang account, i-add ang health check URL (5-minute interval), at i-configure ang notification preferences (email at Slack).

Step 5: I-test ang buong monitoring: mag-cause ng intentional error sa Laravel (hal. divide by zero), i-check ang Sentry dashboard para makita ang error details at stack trace.

Step 6: I-document ang monitoring setup: alin ang gamit para sa errors (Sentry), alin para sa uptime (UptimeRobot), at paano mag-respond sa alerts. I-share sa team para alam nila ang response process.
