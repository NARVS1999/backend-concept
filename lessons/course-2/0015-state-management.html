State Management

Matutunan kung kailan gagamitin ang external state library (Zustand, Context API) vs local state vs server components para sa state management.

Lesson Goal Sa lesson na ito, magagawa mong i-identify kung aling shared state (cart, session) ang kailangan ng external state management at i-implement ito gamit ang appropriate solution.

State Management Decision Framework

Ang tanong lagi ay: kailangan ba talaga ng state management library? Ang sagot ay madalas hindi. Narito ang simpleng framework:

  • Server Components — Kung ang data ay galing sa Laravel API at hindi nagche-change sa client, i-fetch lang sa server component. Walang state management na kailangan.
  • Local State (useState) — Kung ang state ay nasa loob lang ng isang component (form inputs, toggle states, UI states), gamitin ang useState. Hindi mo kailangan ng library.
  • Props Drilling — Kung ang state ay kailangan sa 2-3 components lang at hindi malalim ang hierarchy, i-pass lang via props. Simple pa rin.
  • Context API — Kung ang state ay kailangan sa maraming components na hindi magkaka-related (theme, auth, locale), gamitin ang React Context. Built-in na sa React.
  • External Library (Zustand) — Kung ang state ay complex (cart with operations, real-time data, optimistic updates), gamitin ang Zustand. Mas lightweight kaysa Redux.

Rule of thumb: Magsimula sa pinaka-simple na solution. I-upgrade lang kapag naramdaman mo na ang complexity.

Local State: Ang Unang Choice

Ang useState ang pinaka-polygon na tool. Gamitin ito kapag ang state ay nasa loob lang ng isang component:

'use client';

import { useState } from 'react';

export default function SearchFilter() {
  const [filters, setFilters] = useState({
    query: '',
    category: '',
    minPrice: '',
    maxPrice: '',
  });

  function handleChange(key, value) {
    setFilters(prev => ({ ...prev, [key]: value }));
  }

  return (
    <div className="filters">
      <input
        placeholder="Search..."
        value={filters.query}
        onChange={(e) => handleChange('query', e.target.value)}
      />
      <select
        value={filters.category}
        onChange={(e) => handleChange('category', e.target.value)}
      >
        <option value="">All Categories</option>
        <option value="electronics">Electronics</option>
        <option value="clothing">Clothing</option>
      </select>
    </div>
  );
}

Walang external library na kailangan. Ang useState ay sapat na para sa UI state na hindi kailangan sa ibang components.

Context API: Para sa Shared App State

Ang React Context ay perpekto para sa state na kailangan sa buong app pero hindi naman complex. Ang pinaka-common na use case ay authentication state.

Nakita na natin ang AuthContext sa previous lesson. Narito naman ang theme context:

'use client';

import { createContext, useContext, useState, useEffect } from 'react';

const ThemeContext = createContext(null);

export function ThemeProvider({ children }) {
  const [theme, setTheme] = useState('light');

  useEffect(() => {
    const saved = localStorage.getItem('theme');
    if (saved) {
      setTheme(saved);
      document.documentElement.setAttribute('data-theme', saved);
    }
  }, []);

  function toggleTheme() {
    const newTheme = theme === 'light' ? 'dark' : 'light';
    setTheme(newTheme);
    localStorage.setItem('theme', newTheme);
    document.documentElement.setAttribute('data-theme', newTheme);
  }

  return (
    <ThemeContext.Provider value={{ theme, toggleTheme }}>
      {children}
    </ThemeContext.Provider>
  );
}

export function useTheme() {
  return useContext(ThemeContext);
}

// Usage sa component:
// const { theme, toggleTheme } = useTheme();

Pag gamitin ang Context: Auth state, theme, locale, user preferences — mga bagay na kailangan sa maraming components at nagche-change occasionally.

Hindi gamitin ang Context: Cart data, real-time notifications, frequently updating data. Ang Context ay nagre-re-render ang lahat ng consumers kapag nagbago ang value — hindi ito efficient para sa high-frequency updates.

Zustand: Para sa Complex Shared State

Ang Zustand ay isang lightweight state management library na mas simple kaysa Redux pero mas powerful kaysa Context para sa complex state. Ang bentahe nito ay hindi nagre-re-render ang lahat ng components — nagre-re-render lang ang mga components na gumagamit ng specific na state na nagbago.

I-install ang Zustand:

npm install zustand

Gumawa ng store para sa cart:

// stores/cart-store.js
import { create } from 'zustand';

const useCartStore = create((set, get) => ({
  items: [],

  addItem: (item) => set((state) => {
    const existing = state.items.find(i => i.id === item.id);
    if (existing) {
      return {
        items: state.items.map(i =>
          i.id === item.id
            ? { ...i, quantity: i.quantity + 1 }
            : i
        ),
      };
    }
    return { items: [...state.items, { ...item, quantity: 1 }] };
  }),

  removeItem: (itemId) => set((state) => ({
    items: state.items.filter(i => i.id !== itemId),
  })),

  updateQuantity: (itemId, quantity) => set((state) => ({
    items: state.items.map(i =>
      i.id === itemId ? { ...i, quantity } : i
    ),
  })),

  clearCart: () => set({ items: [] }),

  get totalItems() {
    return get().items.reduce((sum, item) => sum + item.quantity, 0);
  },

  get totalPrice() {
    return get().items.reduce(
      (sum, item) => sum + item.price * item.quantity, 0
    );
  },
}));

export default useCartStore;

Gamitin ang store sa components:

// components/listings/AddToCartButton.js
'use client';

import useCartStore from '@/stores/cart-store';

export default function AddToCartButton({ listing }) {
  const addItem = useCartStore((state) => state.addItem);

  return (
    <button onClick={() => addItem(listing)}>
      Add to Cart
    </button>
  );
}

// components/layout/CartBadge.js
'use client';

import useCartStore from '@/stores/cart-store';

export default function CartBadge() {
  const totalItems = useCartStore((state) =>
    state.items.reduce((sum, item) => sum + item.quantity, 0)
  );

  return (
    <span className="cart-badge">{totalItems}</span>
  );
}

Pansinin na ang AddToCartButton ay hindi nagre-re-render kapag nagbago ang cart count — nagre-re-render lang ang CartBadge. Ito ang efficiency ng Zustand.

Practical: Identifying What State Goes Where

Narito ang practical guide para sa ating Laravel + Next.js project:

State Type Solution Rason
Listing data (from API) Server Component Hindi nagche-change sa client, i-fetch lang sa server
Form inputs useState Local lang sa form component
Modal open/close useState UI state na local lang
Auth user/session Context API Kailangan sa buong app, nagche-change on login/logout
Theme preferences Context API Kailangan sa buong app, rarely nagche-change
Shopping cart Zustand Complex operations, frequently updating, cross-component
Real-time notifications Zustand High-frequency updates, multiple consumers
Search filters URL search params Pwedeng i-share via URL, bookmarkable

Ang URL search params ay isang underutilized na state management technique sa Next.js. Kapag ang state ay kailangan i-share via URL (search, filters, pagination), gumamit ng useSearchParams() instead ng React state.

'use client';

import { useSearchParams, useRouter } from 'next/navigation';

export default function SearchBar() {
  const searchParams = useSearchParams();
  const router = useRouter();

  function handleSearch(term) {
    const params = new URLSearchParams(searchParams);
    if (term) {
      params.set('q', term);
    } else {
      params.delete('q');
    }
    router.replace(`/listings?${params.toString()}`);
  }

  return (
    <input
      placeholder="Search listings..."
      defaultValue={searchParams.get('q') || ''}
      onChange={(e) => handleSearch(e.target.value)}
    />
  );
}

Quiz

Summary

  • Magsimula sa pinaka-simple na state solution — useState muna, i-upgrade lang kapag kailangan.
  • Ang Context API ay perpekto para sa auth, theme, at locale — mga bagay na kailangan sa buong app pero hindi frequently nagche-change.
  • Ang Zustand ay mas efficient kaysa Context para sa complex state — hindi nagre-re-render ang lahat ng consumers.
  • Gamitin ang URL search params para sa state na kailangan i-share via URL (search, filters, pagination).
