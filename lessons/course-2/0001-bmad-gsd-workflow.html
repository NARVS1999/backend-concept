BMAD & GSD Workflow

Matutunan kung paano gamitin ang BMAD framework at GSD workflow para maging structured at efficient ang iyong AI-driven development process.

Lesson Goal Sa lesson na ito, magagawa mong i-define at i-apply ang BMAD at GSD workflows sa isang real project — mula pag-gawa ng documents hanggang sa pag-implement gamit ang AI sub-agents.

Ano ang BMAD?

Ang BMAD (Breakthrough Method for Agile AI-Driven Development) ay isang structured framework na nag-oorganisa ng AI-assisted development. Sa halip na i-prompt ang AI ng "build me an app," gumagawa ka muna ng mga documents na nagsisilbing contract between you and the AI agents.

Ito ang core documents na ginagawa ng BMAD:

  • PRD (Product Requirements Document) — Ang "what" ng project. Ano ang gagawin, para kanino, at bakit. Dito nakalista ang features, user stories, at success criteria.
  • Architecture Document — Ang "how" ng project. Tech stack, folder structure, API design, database schema, at deployment strategy.
  • Design Document — Ang "look and feel." UI/UX specifications, wireframes, component hierarchy, at design system decisions.
  • Experience Document — Ang "journey." User flows, edge cases, error handling, at accessibility considerations.
  • Spec File — Ang "nitty-gritty." Exact API contracts, data models, validation rules, at technical specifications.
  • Error Handling Document — Ang "what if things go wrong." Error codes, retry logic, fallback strategies, at user-facing error messages.

Ang idea ay simple: documents first, code second. Kapag malinaw ang documents, mas madali para sa AI agents na mag-produce ng tama at consistent na code.

Ano ang GSD Workflow?

Ang GSD (Get Shit Done) naman ay ang execution engine. Kung ang BMAD ang "planning phase," ang GSD ang "doing phase." Ito ang workflow na nag-oorganisa kung paano talaga mai-implement ang BMAD documents into working code.

Ang flow ay ganito:

  1. BMAD creates documents — You (or the BMAD agent) produces the PRD, architecture, specs, etc.
  2. GSD reads documents — The GSD system ingests these documents as context.
  3. GSD dispatches sub-agents — Each sub-agent gets a specific task with the relevant document context.
  4. Sub-agents implement — They write code, tests, and configurations based on the specs.
  5. GSD validates — The system checks if the output matches the requirements.

Ang key difference: BMAD = planning framework, GSD = execution framework. Magkasama sila para maging AI-driven ang buong development lifecycle.

Paano Gamitin sa Laravel + Next.js Project

Para sa ating Roxy project (Laravel API + Next.js frontend + MySQL), ganito ang practical application:

Step 1: Gumawa ng PRD gamit ang BMAD

Halimbawa, para sa user registration feature:

## PRD: User Registration

### User Story
As a new user, I want to create an account using my email
and password so that I can access the platform.

### Acceptance Criteria
- User can register with email + password
- Email must be unique in the system
- Password minimum 8 characters
- User receives email verification after signup
- User is redirected to dashboard after verification

### Technical Notes
- Laravel API endpoint: POST /api/register
- Next.js form at /register
- MySQL users table with email, password, verified_at
- Use Laravel Breeze for auth scaffolding

Step 2: Gumawa ng Architecture Document

## Architecture: User Registration

### API Layer (Laravel)
- POST /api/register → RegisterController
- Validates email uniqueness, password strength
- Hashes password with bcrypt
- Creates user record in MySQL
- Dispatches verification email via Mailtrap

### Frontend Layer (Next.js)
- /register page with React Hook Form
- Client-side validation (email format, password strength)
- POST to /api/register
- Show success message, redirect to /login

### Database
- users table: id, name, email, password, email_verified_at, timestamps

Step 3: I-deploy ang GSD para i-implement

Pagkatapos mong maging OK sa documents, pwede mong sabihin sa GSD agent: "Implement user registration based on the PRD and architecture docs." Ang GSD na ang bahala mag-dispatch ng sub-agents para gumawa ng Laravel controller, migration, Next.js form, at tests.

Mini-Project: BMAD Docs for Registration

Subukan mo ito bilang exercise:

## Exercise: Create BMAD Documents

1. Gumawa ng PRD para sa "User Registration" feature
   - 3 user stories
   - Acceptance criteria per story
   
2. Gumawa ng Architecture Document
   - API endpoints (Laravel)
   - Frontend pages (Next.js)
   - Database tables
   
3. Gumawa ng Spec File
   - Exact request/response JSON format
   - Validation rules
   - Error codes
   
4. I-submit sa AI agent for review
   - Ask: "Review this PRD for completeness"
   - Ask: "What edge cases am I missing?"

Ang goal ay maging comfortable ka sa pag-gawa ng structured documents bago ka mag-code. Sa totoong workflow, ito ang gagamitin mo para i-leverage ang AI agents ng todo.

Quiz

Summary

  • Ang BMAD ay planning framework — gumagawa ng documents (PRD, Architecture, Spec, etc.) na nagsisilbing contract sa AI agents.
  • Ang GSD ay execution framework — nagbabasa ng BMAD documents at nag-dispatch ng sub-agents para i-implement.
  • Ang flow: BMAD creates documents → GSD reads docs → sub-agents implement → system validates.
  • Sa Laravel + Next.js project, ang BMAD documents ang magiging source of truth ng lahat ng features.
Interview Angle "How do you structure your AI-assisted development workflow?" — Ito ang pwedeng isagot: gumagamit ako ng BMAD framework para mag-plan at GSD workflow para mag-implement. Nagpo-produce ako ng structured documents bago mag-code para mas accurate at consistent ang output ng AI agents.
