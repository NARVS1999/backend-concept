Indexing

Paano pabilisin ang database queries gamit ang index — at kung kelan ito masama.

Lesson Goal Maunawaan kung paano gumagana ang B-tree index, kung kailan ito effective, at kung bakit hindi lahat ng columns dapat may index.

Ano ang Database Index?

Ang index ay parang talaan ng nilalaman ng libro. Sa halip na basahin ang buong libro para maghanap ng isang topic, titingnan mo lang ang index para malaman kung saang page ito.

Kung walang index, kailangan ng database na i-scan ang bawat row (full table scan) — sobrang bagal para sa malalaking tables.

B-tree Index

Ang default na index type sa karamihan ng databases ay B-tree (Balanced Tree).

  • Hierarchical structure na parang tree
  • Balanced — parehas ang lalim ng lahat ng leaf nodes
  • Effective para sa: =, >, <, BETWEEN, LIKE 'prefix%'
  • O(log n) search time — sobrang bilis vs O(n) ng full scan

Composite Index

Index na may multiple columns:

CREATE INDEX idx_orders_user_date ON orders (user_id, order_date);

Mahalaga ang column order — dapat mauna ang column na ginagamit sa WHERE na may equality filter.

Kailan Masamang Idea ang Mag-index?

  • Every index ay nagda-dagdag ng write overhead — pag may INSERT/UPDATE/DELETE, kailangan i-update din ang index
  • Kumakain ng disk space ang index
  • Hindi nakakatulong ang index sa maliliit na tables (mas mabilis pa rin ang full scan)
  • Hindi effective ang index sa columns na may low cardinality (konting unique values lang, like boolean)
Remember Index everything that slows you down — but measure first. Hindi lahat ng query kelangan ng index.

Mini-Project: Index Performance Test

Gumawa ng table na may 100k+ rows (seed data via agentic script). I-compare ang query speed with vs without index gamit ang EXPLAIN ANALYZE.
