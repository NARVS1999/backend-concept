Phase 2: API Design — Lesson 4 of 4

Rate Limiting

Paano protektahan ang API mo mula sa abuse at accidental overuse.

Lesson Goal Maunawaan ang rate limiting algorithms at kung paano i-apply ang mga ito sa isang real-world API.

Ano ang Rate Limiting?

Ang rate limiting ay isang technique na nagli-limit kung ilang requests ang pwedeng gawin ng isang client sa isang given time window. Proteksyon ito laban sa:

  • DDoS attacks
  • Brute force attacks
  • Accidental overuse (buggy clients)
  • Resource starvation

Rate Limiting Algorithms

Token Bucket

  • Isang bucket na may fixed capacity ng tokens
  • Ang tokens ay naa-add sa bucket sa fixed rate
  • Bawat request ay kumukuha ng isang token
  • Kung walang token, i-reject ang request (429 Too Many Requests)
  • Pwede ang bursts hanggang bucket capacity

Sliding Window

  • Mas accurate kaysa fixed window
  • Gamit ang timestamps para i-track ang requests sa loob ng sliding time window (e.g., last 60 seconds)
  • Iniiwasan ang "boundary problem" ng fixed window
Distributed Systems Problem Kapag maraming server instances, hindi pwedeng in-memory lang ang rate limiter — kailangan ng shared storage (Redis) para accurate ang counting across all instances.

Summary

  • Rate limiting = proteksyon laban sa abuse at overuse
  • Token bucket: allows bursts hanggang capacity
  • Sliding window: mas accurate, walang boundary problem
  • Sa distributed systems, kailangan ng shared storage (Redis)
