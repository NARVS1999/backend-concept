Database Replication & Sharding

Paano i-handle ang paglaki ng database — both reads (replication) at writes (sharding).

Lesson Goal Maunawaan ang pagkakaiba ng replication at sharding, at kung kelan gagamitin ang bawat isa.

Database Replication (Read Replicas)

Pagawa ng kopya ng database sa ibang server. Ang writes ay pupunta sa primary (master), at ang reads ay pwedeng ipamahagi sa replicas (slaves).

Master: INSERT, UPDATE, DELETE
Replica 1: SELECT (read-only)
Replica 2: SELECT (read-only)

Replication Lag

Ang delay sa pagitan ng pag-write sa master at pag-reflect sa replicas. Pwedeng magbasa ang user ng stale data kung nagbasa sa replica bago mag-sync.

Important Replication solves read scaling, NOT write scaling. Lahat ng writes ay sa master pa rin napupunta.

Database Sharding

Paghati ng data sa multiple databases (shards) based sa isang key (shard key). Bawat shard ay may bahagi lang ng data.

Shard 1: users 1-1,000,000
Shard 2: users 1,000,001-2,000,000
Shard 3: users 2,000,001-3,000,000

Sharding Strategies

  • Key-based — Hash ng shard key para i-determine ang shard (consistent hashing)
  • Range-based — Based sa range ng values (e.g., A-M sa isang shard, N-Z sa iba)
  • Directory-based — Lookup table na nagsasabi kung saang shard ang data

Mini-Project: Shard Design

Theoretical exercise — i-design kung paano mo i-shard ang isang users table na may 100 million rows.

Quiz

Summary

  • Replication = kopyahin ang DB para sa read scaling
  • Sharding = hatiin ang DB para sa write scaling
  • Replication lag = delay bago mag-reflect ang writes sa replicas
  • Shard key selection ay critical para sa balanced distribution
