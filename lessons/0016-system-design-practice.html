System Design Practice

Paano lapitan ang system design questions — ang framework na gagamitin sa interviews.

Lesson Goal Matutunan ang structured framework para sa pagsagot ng system design questions at ma-practice ito sa dalawang common problems.

System Design Framework

  1. Clarify Requirements — Tanungin ang interviewer: functional at non-functional requirements, scale estimates
  2. High-Level Design — I-drawing ang main components: client, API gateway, app servers, database, cache, queues
  3. Deep Dive — Pumili ng isang component at i-explore nang malalim
  4. Tradeoffs — Discuss kung ano ang mga compromise na ginawa at bakit

Practice Problem 1: URL Shortener

I-design ang isang URL shortener (like bit.ly). Key considerations:

  • Paano mag-generate ng unique short codes?
  • Database schema: short_code → original URL, created_at, click_count
  • Read-heavy: kailangan ng cache (Redis)
  • Redirection: 301 vs 302 redirect

Practice Problem 2: Simple Notification System

I-design ang notification system. Key considerations:

  • Different channels: in-app, email, push, SMS
  • Queue-based para hindi ma-block ang main application
  • Template system para sa consistent formatting
  • Rate limiting para hindi ma-spam ang users

Mini-Project: Design Practice

I-design ang "URL Shortener" at "Simple Notification System" gamit ang framework sa itaas. Isulat ang design bago tignan ang solutions online.
