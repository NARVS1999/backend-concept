Vertical vs Horizontal Scaling

Paano lumalaki ang isang system mula sa isang server papuntang milyun-milyong users.

Lesson Goal Maunawaan ang tradeoffs ng vertical at horizontal scaling, at kung bakit kailangan ang statelessness para sa horizontal scaling.

Vertical Scaling (Scale Up)

Magdagdag ng mas malakas na resources sa iisang server — mas mabilis na CPU, mas maraming RAM, mas malaking disk.

  • Pros: Simple, walang code changes, walang distributed system complexity
  • Cons: May upper limit (di pwedeng infinite ang specs ng isang machine), single point of failure, mas mahal per unit of compute

Horizontal Scaling (Scale Out)

Magdagdag ng mas maraming servers sa halip na palakasin ang isa.

  • Pros: Theoretically unlimited (dagdag lang ng servers), fault-tolerant (may iba pang servers kung may isang mamatay), cost-effective
  • Cons: Complex — need load balancer, distributed data management, statelessness

Statelessness: Requirement para sa Horizontal Scaling

Kung naka-store ang session data sa local memory ng isang server instance, hindi pwedeng i-forward ang next request ng same user sa ibang server.

Solution: i-store ang session sa shared external storage (Redis, database) para kahit saang server mapunta ang request, parehas ang experience.

Summary

  • Vertical scaling: palakasin ang isang server — simple pero may limit
  • Horizontal scaling: dagdagan ang servers — unlimited pero complex
  • Statelessness ay critical para sa horizontal scaling
