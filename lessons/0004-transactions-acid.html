Transactions & ACID

Paano siguraduhin na ang database operations ay reliable kahit may failures.

Lesson Goal Maunawaan ang ACID properties, isolation levels, at kung paano gamitin ang transactions para sa data integrity.

Ano ang Transaction?

Ang transaction ay isang group of operations na ginagawa bilang isang unit. Either lahat mag-succeed, o lahat mag-fail at i-rollback.

Classic example — bank transfer:

BEGIN TRANSACTION;
UPDATE accounts SET balance = balance - 500 WHERE id = 1;
UPDATE accounts SET balance = balance + 500 WHERE id = 2;
COMMIT;

Kung mag-crash ang server pagkatapos ng first UPDATE pero bago ang second, awtomatikong ibabalik ng database ang lahat (ROLLBACK).

ACID Properties

  • Atomicity — Lahat ng operations sa transaction ay either lahat mag-succeed o lahat mag-fail.
  • Consistency — Ang database ay nasa valid state bago at pagkatapos ng transaction.
  • Isolation — Ang concurrent transactions ay hindi dapat mag- interfere sa isa't isa.
  • Durability — Kapag na-commit ang transaction, mananatili ang changes kahit mag-crash ang system.

Deadlocks

Nangyayari kapag dalawang transactions ay naghihintay sa isa't isa para mag-release ng lock. Detection: awtomatikong dine-detect ng database at ni-rollback ang isang transaction.

Summary

  • Transaction = group of operations na either lahat mag-succeed o lahat mag-fail
  • ACID: Atomicity, Consistency, Isolation, Durability
  • Higher isolation level = more data safety pero lower concurrency
  • Deadlocks ay awtomatikong dine-detect ng database
Interview Angle "Ano ang mangyayari kung mag-crash ang server sa gitna ng transaction?"
